## 后续失败分析和完成标准

每个任务记录官方分数、Agent 终态、环境/依赖、模型请求、预算、测试输出、补丁或产物，以及源码/镜像/任务哈希。
分类至少保留环境、Provider、预算、harness、任务解法和证据不足六种；不能强行把所有失败归为“模型”或“harness”二选一。

| 观察 | 归因方法 |
|---|---|
| 参考解也失败、容器无法启动、依赖下载失败 | 先检查环境或验收器，不计为模型能力证据 |
| 题面/工具结果丢失，补丁收集错误，状态污染，提前终止 | 用确定性复现和轨迹定位 Bot/harness；保留修复前后同条件对照 |
| 请求超时、鉴权或限流错误 | 单独记录 Provider/网络问题 |
| 达到步骤、时间或费用上限 | 记录预算原因及停止点，不据此直接认定模型能力不足 |
| 环境和参考解正常，但生成实现未通过测试 | 先记为解法失败；结合最小复现、重复运行及受控 harness 对照，才提高模型归因置信度 |
| 同时存在多种因素或无法复现 | 允许多因素和证据不足，说明进一步需要的实验 |

执行完成要求是 40 题均有可追溯记录、失败均有证据和归因置信度、未通过/异常完整保留、费用不超过用户批准的执行边界、
资源清理完成、报告可由原始结果重建。模型通过率是测量结果，不是预检完成标准。
