# bot 开发演进记录：从 CLI MVP 到可审计的长任务 Agent

> 整理日期：2026-09-18。代码与统计基线：`eca866e`（当日 15:18，Asia/Shanghai）。
> 覆盖 2026-07-17—2026-09-18 的 Git 历史、设计、实现和评测记录。
> 本文汇总既有证据，没有重新运行模型、公开基准或硬件验收。历史指标保留原实验口径。

bot 的发展主线是：先建立能执行工具的本地 CLI，再补齐会话、安全和子任务能力；随着任务变长，重点转向上下文预算、可恢复压缩、记忆和执行控制；最后通过公开基准、固定输入实验和真实运行复盘，把“能运行”逐步推进到“能解释运行结果、定位失败并验证修复”。

项目定位仍是通用、本地优先的工程 Agent。鲲鹏性能分析通过 Skill 和工具适配器扩展，核心不绑定某一个领域。当前提供 CLI 和 Web 入口，支持持久会话、受控工具执行、子 Agent、长期记忆、上下文压缩与运行审计；部分高级方案仍处于实验或设计阶段。

本文是项目发展总览。当前使用方式以[项目 README](../README.md)为准，逐项能力见[实现状态](architecture/implementation-status.md)，完整提交及来源指纹见[本次历史快照](data/development-history-20260918.json)。

## 3. 从记录中可以还原的开发流程

仓库呈现的是逐步形成的迭代方式，不是每次提交都严格执行相同流程。完整的一轮通常包含以下环节：

1. **从实际运行定位问题。** 保存 SQLite/JSONL、请求快照、工具结果、usage 和最终产物。例如公开基准发现未交付文件，长任务发现重复查询，09-16 会话暴露摘要输出撞限。
2. **把问题拆成可核验的层。** 区分 Provider 协议、规划预算、摘要生成、发布恢复、工具执行、宿主环境和最终验收，避免用一个零分或异常概括全部原因。
3. **调查现有实现并写方案。** 在 `research/` 固定外部实现版本，在 `designs/` 明确候选、失败保护、默认开关和待验收范围；最终行为以代码为准。
4. **先冻结比较条件。** 保存代码/wheel、配置、任务、请求及来源哈希；预先记录运行顺序、上限、验收规则和环境异常处理。实验修改与冻结运行包分开管理。
5. **实现并验证失败路径。** 用确定性 Provider、本地进程和事务故障覆盖空输出、截断、取消、超时、发布失败、重启和重复调用；再按需要补充真实 API 小样本。
6. **独立验收任务结果。** 使用文件/JSON Schema、实际工具结果或官方容器测试；同时记录运行是否正常结束。失败请求、兜底、预热和缺失 usage 均保留。
7. **复盘后决定默认值。** 例如双路径成为默认，而重复限制仍默认观测、自动恢复仍关闭；研究方案或离线通过不自动视为已全面启用。
8. **同步文档和审计附件。** 架构说明描述当前行为，评测报告保留历史条件，JSON 保存量化证据，过时方案进入归档；提交记录串联每次变化。

代表性闭环是：**09-16 事故 → 24 次预算实验 → 48 次提示实验 → `8f5c7bc` 落地 → gaming 连续运行观察 → 长上下文专项 → `eca866e` 独立兜底设置调整**。这些样本的用途不同，应顺着决策关系阅读，而不是拼成一条统一成功率曲线。

### 4.4 四策略选型与扩大输入预算的反例

09-13 的四策略实验在同一道 `path-tracing-reverse` 上各保留 3 场有效结果，共 12 场；实际执行 13 场，其中一场 CURRENT 因宿主休眠按预先记录的规则排除。模型为 Flash、thinking 关闭，运行包固定在 `99d70d8`。

| 策略 | 整题通过 | 已知费用中位数，USD | Agent 时间中位数 | 全程加权缓存率 | 摘要发布 / 启动 |
|---|---:|---:|---:|---:|---:|
| CURRENT | 0/3 | 0.6477 | 18.84 分钟 | 78.60% | 27/27 |
| A | 0/3 | 0.6327* | 25.16 分钟 | 90.50% | 10/15 |
| B | 0/3 | 0.6931* | 29.24 分钟 | 83.29% | 7/15 |
| 双路径 `a_fallback` | 3/3 | 0.5135 | 16.92 分钟 | 90.31% | 13/16 |

星号组含费用下界；表中金额采用冻结比较费率，包含失败场。CURRENT 的摘要全部发布，整题仍全部失败；A 的缓存率略高于双路径，也没有整题通过。双路径同预算净释放率中位数为 57.55%，A/B 约为 57%，并无明显更高的释放率。

这支持继续验证双路径，不证明稳定的跨任务成功率或单一因素因果关系。来源：[三轮复测](evaluations/context-strategy-flash-repeats.md)、[归因复核](evaluations/context-strategy-flash-causal-analysis.md)。

09-14 又对同题各做一次不同输入预算的整题实验：

| 配置输入预算 | 实际主输入峰值 | 已知全阶段缓存率 | 官方验收 | 运行结果 |
|---|---:|---:|---|---|
| 128K | 96,104 | 95.13% | 3/3 | 正常完成，8.20 分钟 |
| 256K | 174,531 | 96.97%* | 2/3 | 达到时间上限，29.27 分钟 |
| 512K | 208,271 | 97.62% | 2/3 | 主响应输出撞限，18.70 分钟 |

这里 K=1,000；256K 组缺一条 terminal usage，命中率仅基于已知用量。配置更大并不意味着实际输入达到该长度，两场失败都是图像验收未过，不能把编译通过当成整题成功。这是三条不同执行轨迹，不能证明扩大预算必然降低质量。来源：[输入预算实验](evaluations/context-length-flash-cache.md)。

### 4.5 从摘要事故到最新默认设置

| 时间 / 实验 | 样本 | 结果与意义 |
|---|---|---|
| 09-16 事故 | 一个调查会话，6 个操作、7 次摘要请求 | 操作成功 1/6；请求成功 1/7，其余 6 次均 `length` |
| 09-17 预算对照 | 四个冻结独立输入，各组重复两次，共 24 次请求 | 旧提示共享 8K：默认 thinking 0/8、关闭 0/8；总额度 16K 的 thinking 组 8/8，但仅 3/8 完整正文 ≤8K |
| 09-17 仅加强内容取舍 | 同一批困难输入的提示实验 | 默认 thinking 1/8、关闭 6/8 候选通过 |
| 09-17 取舍＋尾部提醒 | 第二轮自适应补测 | 默认 7/8、关闭 8/8；通过候选正文均值约 3,062 / 2,996 tokens |
| 09-18 gaming 连续运行 | 单个 59 分 02.646 秒 Run，486 次主请求、513 次工具请求 | 10/10 前缀摘要首次生成并发布；摘要输入缓存率 95.29%，摘要请求累计 154.566 秒，占总时长 4.36% |
| 09-18 长上下文专项 | 三档 × 三种路径 × 三次，27 次；另加 6 次诊断 | 共 33 次摘要、32 次发布；主矩阵前缀开启 9/9、独立关闭 9/9、独立开启 8/9 |

提示改进两轮共 48 次真实请求；与预算对照的 24 次分别计数。旧提示结果是前序实验基线，第二轮没有同时重跑旧组。gaming 的 10 次属于一条相关轨迹，也没有旧提示同轨迹对照，不能将全部改善归于单一改动。

长上下文专项的 K=1,024，使用同一真实任务的嵌套历史重建 96K/256K/512K 请求，保留尾部专门控制在约 4K；与上一节的整题输入预算实验不同。32 个已发布样本恢复后均逐字保留用户锚点，但这项检查不代表摘要语义完整。

本阶段仍有明确反例：

- gaming 后段摘要传播了错误工具经验；成功发布没有防止错误因果解释延续。
- 长上下文实验有摘要混入声明覆盖范围以外的保留尾部，也有正常模式试玩要求被省略。
- 唯一失败返回 `stop`，产生 5,010 个 reasoning tokens、正文为空；33 次没有真实 `length`，不能据此宣布长推理截断风险消失。
- 全部 15 次前缀摘要新增 reasoning 为 0，即使显式开启也如此；这是可观测结果，尚未确定服务端内部原因。

随后 `eca866e` 将独立兜底默认设为关闭 thinking，优先保证正文产出；主任务及前缀设置保持继承。关闭并不保证正文、事实或下游任务一定正确，失败仍不得推进摘要游标。

来源：[事故](evaluations/compaction-incident-20260916.md)、[24 次预算对照](evaluations/compaction-thinking-budget-20260917.md)、[48 次提示实验](evaluations/compaction-selection-20260917.md)、[gaming 复盘](evaluations/gaming-run-analysis-20260918.md)、[长上下文专项](evaluations/long-context-compaction-20260918.md)、[最新默认值](designs/compaction-isolated-thinking.md)。

## 5. 截至基线的实现状态和重要取舍

下表描述已提交代码的默认值或能力，具体工作区配置可以覆盖；当前代码入口为[配置模型](../src/bot/config/models.py)。

| 方向 | 已落地的结果 | 仍需区分的边界 |
|---|---|---|
| 运行入口 | CLI 与 Web 共用运行核心、会话、权限和审计；支持运行中补充与取消 | 浏览器断线恢复不等于进程退出后任务仍能后台存活 |
| 任务组织 | 持久 TODO、Markdown Agent 定义、前后台子任务、mailbox、worktree patch 采用 | 当前为进程内一级子 Agent，不是递归、对等或跨机器 Agent Team |
| 上下文 | 预算规划、工具整组保护、外置与回读、原始用户锚点、事务化单活动摘要 | 摘要结构、来源哈希和预算通过，不证明事实完全正确 |
| 压缩默认 | `a_fallback`，一次前缀机会、必要时一次独立兜底；独立 thinking 默认关闭 | CURRENT/A/B 仍有历史/可选路径；A+D 主动交接未成为默认 |
| 摘要长度 | 约 3K 软目标；取消旧正文硬门限，保留生成截断与完整恢复预算检查 | 完整长摘要不因超过软目标直接拒绝，亦不保证每份正好 3K |
| 记忆 | Markdown 显式/自动记忆，默认 on-demand Router，历史归因要求证据回读 | 小规模 catalog 记忆切换仍是设计，不能写成已替换 Router |
| Skill | 新会话默认 history，Run 隔离、版本绑定、正文交付和压缩恢复 | 旧会话有 legacy 兼容；通用投影、独立微裁剪等尚未完成 |
| 执行可靠性 | 进程清理期限、响应完整性门禁已生效；重复检测可强制，恢复有预算 | 重复检测默认 observe，自动恢复默认关闭；平台与自然长任务覆盖仍有限 |
| Provider | thinking 由请求决定，发送时区分已有 reasoning 与空字段占位 | 协议占位不代表还原历史思考；已测端点之外仍需兼容验证 |
| 可观测性 | 跨会话分析、来源去重、审批等待、净耗时和停止原因审计 | 缺结束时间或 usage 标为未知；completed 不自动转换为验收通过 |
| 鲲鹏能力 | KSYS/DevKit Tuner 结构化适配；缺环境时提供手动命令 | Linux/鲲鹏 ARM 工具版本、权限与采集开销仍需目标环境验收 |

应优先按最新提交解释有冲突的历史文档。例如 08-29 Router 报告保留了当时的 thinking 兼容行为，09-18 已由 `7a94d7d` 替换；09-17 的实现状态也早于本次最终兜底配置。历史实验数据保留，当前行为分别查看[协议修复](evaluations/thinking-replay-fix-20260918.md)与[独立兜底设计](designs/compaction-isolated-thinking.md)。

## 7. 尚未闭环的方向

截至本次基线，下列事项仍应保留为待验证或待实现，不能写进已完成成果：

1. **更广的任务有效性。** 公开 40 题尚未完成；双路径 3/3 来自同一道题，需要不同任务、多次运行及跨模型对照。
2. **摘要事实保真。** 已发现错误经验传播、声明范围越界和条件遗漏；需要检查多次压缩后事实、反证、回读行为及下游决定，不能只看八章节和发布成功。
3. **跨 Run 压缩恢复。** 快照缺失、失败退避不跨 Run 继承、总生成额度与恢复预留耦合仍有改进空间。
4. **长任务恢复的真实收益。** 重复限制与有限恢复已有离线和小样本验证，默认仍渐进启用；自然循环误拦率、整题收益及平台差异尚未充分验证。
5. **最终交付物与验收版本绑定。** P1 仍未实施，不能依赖“前一次测试通过”证明最后修改后的文件正确。
6. **记忆与 Skill 后续设计。** 小规模记忆切换、Skill 通用历史投影和微裁剪尚未形成完整生产闭环；A+D 自主交接的 L2/L3 尚未执行。
7. **领域与部署验收。** 鲲鹏 ARM、KSYS/Tuner、其他模型服务和不同操作系统仍需各自环境验证。

这些条目的状态依据见[实现状态](architecture/implementation-status.md)、[小规模记忆定稿](designs/small-memory-switch-design.md)、[可靠性方案](designs/task-reliability-recovery-design.md)、[优化复盘](evaluations/compaction-optimization-retrospective-20260918.md)及[长上下文实测](evaluations/long-context-compaction-20260918.md)。
