# 为什么双路径三次都通过：结果复核与归因边界

日期：2026-09-13。针对 [三轮复测](context-strategy-flash-repeats.md) 的后验分析。
本次没有再次调用模型，也没有修改运行时；只对齐已保存轨迹、阅读摘要和源码，并独立重放产物。

结论应收紧为：双路径在这三条有效轨迹上表现最好，成功产物得到独立验证；现有对比不能
单独证明兜底、缓存、提示词或输入组装各贡献了多少。优先继续验证双路径是选型判断，
不是已建立的因果结论或稳定成功率估计。

## 通过结果真实，二元评分会放大表现差距

使用已有任务镜像，在新建、断网容器内重新静态编译所有七份已保存源码，再放入只含
该可执行文件的空 chroot 运行。参考图像同时与冻结任务的 `orig.c` 重新构建结果核对，
两份参考 PPM 完全一致。这里只重放产物，不增加 Agent 测试样本数。

| 产物 | 与参考不同的颜色通道数 / 1,440,000 | 图像相似度 | gzip 字节数 |
|---|---:|---:|---:|
| 双路径第 1 次 | 0 | 约 1.0 | 1,098 |
| 双路径第 2 次 | 0 | 约 1.0 | 1,358 |
| 双路径第 3 次 | 0 | 约 1.0 | 1,086 |
| A 第 3 次 | 1,202,204 | 0.92033 | 1,559 |
| B 第 3 次 | 1,187,231 | 0.92136 | 1,735 |
| CURRENT 替补 | 1,431,309 | 0.91116 | 1,547 |
| CURRENT 原第 3 次，环境排除 | 46 | 0.99999649 | 1,486 |

双路径三份 PPM 文件的 SHA-256 都与参考相同，不只是勉强越过 0.995 门槛。源码检查
显示它们独立计算射线、球体、地面和光照，没有调用原程序或存储整张图像。
这里的逐字节一致指 PPM 图像文件，不表示本次重新审计了全部 stderr 字节。

另外三组第三次均能留下可编译源码，官方通过 2/3 子项，只是图像不合格。
因此“整题通过 0/3”不能读成“没有任何实现进展”。不过它们的大量像素差异也说明
失败不仅是一个浮点低位误差。被环境排除的 CURRENT 产物再次通过独立重放，也说明
CURRENT 本身有解决此题的能力；原排除规则和主报告统计保持不变。

## 三个简单解释都不充分

| 解释 | 观察证据 | 能支持的结论 |
|---|---|---|
| 缓存越高，越能完成任务 | A 全程缓存率 90.50%，双路径 90.31%；A 摘要缓存 91.46%，双路径 75.33% | 缓存率不能解释这次完成率排序 |
| 双路径压得更多，所以更强 | A/B/双路径净释放率中位数为 57.00% / 56.94% / 57.55% | 释放率差异很小，不能作为主要解释 |
| 多一次兜底就带来 3/3 | 双路径第二轮两次发布都来自前缀，没有采用任何独立摘要，任务仍通过 | 兜底有实际收益，但不足以单独解释全部成功 |

兜底确实救回了三次前缀失败，属于直接观测到的工程收益；不能进一步推断如果没有
这三次兜底，三场任务就一定失败。

输出额度也有差异：A 摘要 8K，双路径前缀 32K。但这批 A 的 14 个摘要响应没有
`finish_reason=length`；双路径 13 个被采用的摘要最多只生成 5,585 completion tokens。
双路径有一份被拒绝的前缀响应达到 8,463，但未进入主上下文。因此不能将本批成功
解释为“成功摘要必须依赖超过 8K 的生成”。输出参数是否间接影响生成仍需单变量验证。

## 更值得验证的解释：摘要改变了后续解决问题的方式

### 提示词增加了什么

双路径使用 `FALLBACK_SUMMARY_INSTRUCTION`，相对 A 的旧交接指令，明确增加：

- 助手说法重复或出现较晚，不代表正确；旧摘要的未核实状态不得升级成事实。
- 区分计划、执行、返回结果和验收通过。
- 保留互斥解释、反证、关键数值和可回读来源。
- 下一步只核对当前行动所依赖的存疑结论，不要求重读全部历史。

这些规则可能让摘要成为更有用的后续工作说明，同时删去重复探索和错误推断的冗余。
这仍是机制假设；三次成功并不等于摘要整体事实正确率得到测量。

### 一条能看到行为变化的轨迹

双路径第三轮第 3–32 步连续重复 `strings -n 4 /app/mystery`，共 30 次。
摘要在第 14、23、32 步之后发布；第三份明确指出重复没有产生新信息，尚未运行或
反汇编目标。第 33 步随即检查可用工具、运行 `mystery`，然后开始读取反汇编。
这发生在纯前缀路径中，该场第一次采用独立摘要要到第 118 步之后。

但必须同时保留反例：A 第三轮在第 22 步后发布第一份摘要，第 23 步也结束了
重复 `nm`，转向过滤符号和读取反汇编。新方案前两份摘要同样没让 `strings` 循环停止。
所以“摘要后换行动”是观察到的时间顺序，不是新提示词必然有效或仅新方案有效的证明。

### 一条能看到错误被保留、继续纠正的轨迹

双路径第二轮第一份摘要把栈偏移推断自相矛盾标为“不可信，待核实”，保留反汇编
引用，下一轮实际调用 `load_context_reference` 回读相应内容。
第二份摘要明确保留候选程序尚未通过验证，以及自写对比工具观测到的
“1,440,000 个通道中 721,461 处不同”、错误开始的像素位置、球体错误呈灰色等信息，
并把修正颜色和核对地面光照列为下一步。主模型继续反汇编、采样、修正，最后输出正确图像。

这支持“保留未通过状态和可执行的纠正线索有帮助”的解释。但同一批摘要也有错误推断，
不能把这个成功案例当作语义无误保证；更不能比较不同输入上的摘要就断言新提示词更准确。

### 其他方案受到额外运行缺陷拖累

B 第二轮超大工具组无法进入叶节点，后续请求准备区间合计 1,076 秒；B 第三轮合并摘要
反复超长，8 个已生成叶节点没有进入已发布根。A 也发生摘要输入超过上限、长时间重复命令。
这些问题会消耗有限时间和费用，使本来就有不确定性的解题更难完成。

不过，并非所有错误都由摘要引入。例如 B 第三轮在第 22 步写入最终保留的错误源码，
首次摘要要到第 35 步之后才发布。该摘要把 `normalize(1,1,-1)` 写成相机方向，
而正确实现把它用于光照；错误在摘要前已存在，摘要可能沿用了它。
CURRENT 三次有效场都是主响应输出触顶，摘要请求却全部成功。

## 为什么还不能认定稳定提升

四组并非从同一个中间状态分叉。第二轮双路径在第 4 步已查询 `nm`、第 6 步读反汇编，
首次摘要在第 21 步后；A 同轮第 5、7 步已经出现超长无效工具参数，首次压缩启动在
第 7 步后、首次发布在第 39 步后。这些摘要前就出现的差异，不能追溯成后续摘要的收益。

同时改变的因素包括旧/新提示词、完整 frame/真实出站快照、摘要额度、回退路径、
覆盖范围校验及运行中的成功/失败切换时点。只有一道题、每组三次，模型轨迹、执行顺序
和缓存状态仍会影响结果。它是值得跟进的信号，但不是“设计让能力稳定从 0% 到 100%”。

最小的下一步是选定同一份压缩前检查点，克隆文件与会话状态，固定相同输入、额度和
主模型，只比较 A 旧摘要指令与新摘要指令；每组重复三次、先续跑 10–20 步，观察
是否离开重复调用、是否纠正关键错误、是否得到有效文件变化。随后再单独测试兜底。
这样比继续各自从头跑整题更容易识别提示词的贡献；短程改善也仍需完整验收确认。
