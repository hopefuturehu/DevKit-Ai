## 最终修改

[共用提示与尾部提醒](../../src/bot/compaction/strategies.py)增加以下要求：

- 旧摘要与新增原文统一重新筛选，旧摘要里的信息不自动获得保留资格。
- 优先当前请求、有效硬约束、未完成事项、阻塞及继续工作所需证据。旧任务仅保留仍有影响的成果。
- 已完成工作按成果合并；不复述工具调用过程、旧验证细节或全部访问过的文件。
- 普通历史问题不作为硬约束，已经回答的问题不重新变成待办。
- 一条事实只放一个章节；精确值、反证和不确定性仍需保留，过程细节可换成已有回读线索。
- 八章节仍全部必需，建议总篇幅约 3K。尾部再次要求短要点、按当前任务重写，不续写旧摘要。

前缀路径在原出站快照之后追加交接指令与覆盖映射，提醒放在最后；原 system、工具定义、
历史及请求参数保持原样。独立路径为 `system 指令 → user 历史 JSON → user 交接提醒`，
历史 JSON 内容与覆盖范围不变。新增提醒是运行器指令，不是伪造的历史用户消息，
不会写入原会话证据或推进覆盖游标。

本轮真实模型实验只覆盖独立路径。前缀快照保持与两条路径的接入由现有运行时测试核验，
没有据此宣称测得了真实前缀缓存收益。旧 A/B/CURRENT 提示不随本次改动更新。

正文范围及均值只统计完整候选；thinking 和耗时统计全部请求。提供商默认不表示每次一定

唯一失败为 `p248-r2-current-selection_tail`：reasoning **7,030**，正文 **1,164**，

因此可以说体积接近目标、截断显著减少，不能说已形成严格 3K 上限。当前默认配置对应
7/8 这一组；显式关闭 thinking 只是实验条件，没有在生产自动切换。

第二轮是观察第一轮后进行的自适应补测，未同时重跑对照。离线确认其 16 个出站请求与

位置，本轮**没有单独隔离位置和措辞各自的贡献**。

## 内容确实减少了什么

对关闭 thinking 的每组 8 份正文做固定文本探查，包含失败时已返回的部分正文：

| 历史信息出现次数 | 旧提示 | 仅新 system | 新 system＋尾部提醒 |
|---|---:|---:|---:|
| 鹈鹕 / pelican 旧任务 | 8/8 | 6/8 | **0/8** |
| SVG 9,521 字节 | 8/8 | 5/8 | **0/8** |
| SVG 元素计数（41 path / 17 circle） | 8/8 | 0/8 | **0/8** |
| 目录 20,689 文件 | 8/8 | 6/8 | 4/8 |
| 已出现 Critical Context 章节 | 1/8 | 8/8 | 8/8 |

第一轮新 system 的两份截断文本虽然进入了最后章节，仍未完成，因此继续判失败。
文本探查只说明这些细节是否出现，不等同于所有无用信息都已删除，也不等同于事实保真。
默认 thinking 的最终组也完全去掉了鹈鹕任务和 SVG 字节、元素计数；目录数量仍出现 1 次。

完整候选的 15/15 都保留了 `on_demand` 和抽取器 `2048` 预算这两项字符串。
另对最终版 6 份完整候选作定向人工检查：记忆按需读取、预算与建议未实施的状态仍有记录；
开源调研断点没有被写成已经完成对比。`p238-r1-current-selection_tail` 明确写当前无未答
请求，把助手提出的修复方案与用户尚未回应区分开，并将抽取失败原因写成待验证假设。

不过正确性仍有问题：

- `p238-r1-thinking_off-selection_tail` 一边称最新请求未答，一边说助手已给出分析。
- 有的摘要把“检查下代码吧”扩展成用户禁止一切推断，或仍把普通历史问题当硬约束。
- `p248-r1-current-selection_tail`、`p253-r2-current-selection_tail` 等仍保留“空正文异常
  在 USAGE 事件之前”的错误解释；相同输入的工具消息 211 显示，USAGE 在流循环中处理，
  空正文检查在循环之后。部分摘要会给整体归因加上“假设”，但没有消除局部错误断言。

人工检查是选定样本和选定事实的核对，不是全面准确率评测。没有把篇幅减少或校验通过
当成事实准确性的替代指标。第一轮 4 份、第二轮 6 份检查的样本哈希及证据行号见机器记录。
