# Flash 256K / 512K 真实任务失败复盘

日期：2026-09-14。分析对象是 [三档缓存实验](context-length-flash-cache.md) 的
`path-tracing-reverse` 原始轨迹。没有重新调用模型或重跑任务。
在全部实验结束后，额外对照了任务构建二进制所用的 `environment/orig.c`；该文件在
任务容器构建时已删除，以下源码对照属于事后分析，不是提供给参测 Agent 的信息。

**256K 因时间上限结束，背后同时存在工具终止等待和错误的逆向结果；512K 在棋盘格
分析中进入重复生成，耗尽单次输出额度。两组最终文件均未满足图像相似度要求。**

| 项目 | 256K | 512K |
|---|---|---|
| 直接结束原因 | `max_wall_time_seconds`，1,740 秒 | `model_output_limit`，单次输出 32,768 tokens |
| 完成的主步骤 | 114；第 115 次请求被时间限制中断 | 111；最后一次 `finish_reason=length` |
| 官方图像余弦相似度 | **0.8722718320** | **0.9654450602** |
| 官方要求 | ≥0.995 | ≥0.995 |
| 另外两项验收 | 文件存在、编译通过 | 文件存在、编译通过 |
| 实际主请求输入峰值 | 174,531 | 208,271 |
| 压缩次数 | 0 | 0 |

余弦相似度不是“相同比例的像素”。验收失败详情、原始事件位置和文件哈希见
[证据附件](../data/context-length-flash-failures.json)。

## 256K：工具等待消耗时间，交付代码仍有明确错误

### 一次取消操作等待了约八分钟

第 57 步明确要求停止过慢的暴力搜索、转回反汇编。`terminate_process` 从
10:16:52.316482 UTC 到 10:24:50.010517 才返回，等待 **477.69 秒**，相当于
整组 1,740 秒运行额度的 **27.45%**。这段时间包含在任务运行时间内，不能解释为
模型处理长上下文耗时。

执行中的只读进程快照显示：原启动进程组已经退出，`timeout 600` 和其 `geo` 子进程
仍在另一个进程组中运行；直到它们自身的超时到期，工具才返回。

[`LocalExecutionTarget`](../../src/bot/execution/local.py:168) 终止登记的进程组，
随后等待 `managed.finished`；监控任务在设置完成事件前，还会等待 stdout/stderr
读取结束。离开原进程组的后代仍可能持有这些管道，使取消操作继续等待。

本次另外使用同一实现做了一个有界本地复现：启动持有输出管道、4 秒后自行退出的
子进程。保持同组时，取消耗时 **0.051 秒**；子进程调用 `os.setpgrp()` 离开原组时，
取消耗时 **4.013 秒**，一直等到子进程退出。两次结束后均无存活的受管进程。
复现环境是 macOS / Python 3.14.5，支持上述实现问题；原 Linux/QEMU 任务没有采集
Python 调用栈，无法进一步断定当时具体停在哪一个等待语句。

### 逆向过程没有收敛，拟合结果也没有写回最终文件

最后一次修改 `/app/mystery.c` 的工具记录在 10:30:39，保存的相机代码为：

```c
float len = sqrtf(vy*vy + w*w + 1.0f);
V d = {0, vy/len, -1.0f/len};
```

**光线 x 分量被固定为 0。** 虽然 `w` 进入了长度计算，它没有进入方向的 x 分量，
所以相机光线几何仍然错误。参考实现的光线方向包含随列号变化的 x 分量，并且
横纵像素坐标分别按 `width - 1`、`height - 1` 归一化。

同一份交付代码还使用了拟合光照方向 `(0.26311, 0.93894, -0.22175)`，而参考实现
是归一化的 `(1, 1, -1)`；棋盘格的明暗映射及暗色值也有偏差。故此次失败不能只归为
“少了一点调试时间”或“浮点误差”。

10:30:46 的实际编译比对已经报告 835,196 个 RGB 通道值差异大于 1。之后 Agent
继续在 `/tmp/w` 中写拟合探针；临近结束时，探针给出球体包围盒接近参考，但天空样本
仍有 121,897 / 208,800（58.38%）像素不匹配。**这个包围盒结果来自探针，不是
最终交付文件的验证。** 从后续工具参数可见，拟合发现没有再写回 `mystery.c`。

第 115 次请求才表示应停止拟合、重新精读反汇编，随即触及时间限制。Agent 的最终
总结声称“球体几何正确”，不能代替实际文件和官方验收的证据。

判断：工具取消问题是明确的耗时因素；相机、光照等还原错误，以及探针结果未落实到
交付文件，是明确的产物问题。消除那 477.69 秒等待可能增加修复机会，但不能从本轮
推断一定能通过。

## 512K：棋盘格还原错误，随后单响应进入重复生成

### 交付文件的棋盘格公式有两个具体错误

最后一次成功修改棋盘格代码的工具记录保留了：

```c
float c = ((int)floorf(p.x + p.z) & 1) ? 0.9f : 0.4f;
```

参考实现则分别对 x、z 取 floor，再判断两者和的奇偶；**偶数用 0.9，奇数用 0.4**。
因此这里同时存在“先相加再取整”和“明暗对应反转”两个错误。

例如该组探针给出的 row 500 / col 0 坐标约为 `x=-2.98753, z=-2.24065`，
参考逻辑得到 `floor(x)+floor(z)=-6`，使用浅色；row 530 / col 0 约为
`x=-2.59870, z=-1.94902`，得到 -5，使用深色。这正好解释 Agent 反复纠结的
“x 的 floor 相同，为什么两行明暗不同”：z 的 floor 已经变化。

后续轨迹大量测试坐标与平面参数猜想，但没有将正确的棋盘格逻辑写回文件。官方相似度
为 0.965445，仍低于 0.995。此次未对修正后的整个程序重新验收，因此不能断言只改
这一个表达式就必然整题通过。

### 最后一次输出是重复循环，不是正常工作刚好需要更多额度

第 111 次主响应记录了：

- 输入 208,271 tokens；输出恰好 **32,768 tokens**；`finish_reason=length`。
- 正文 **115,292 个字符**，无 reasoning 字段内容，**没有工具调用**。
- 按证据附件给出的句子切分规则，同一段推测中的完整句子各重复约 **121–123 次**。
  中段、末段均在反复讨论 `point.x`、同两行的奇偶、同一个平面求交公式。

这些推理文字位于普通 content 流中，虽然配置的 thinking 已关闭。轨迹说明模型在
一次响应内部出现重复生成；最后一轮没有实际执行它反复声称将要做的探针。

现有 [`AgentRunner`](../../src/bot/core/agent.py:1575) 在无工具调用且
`finish_reason=length` 时直接进入 `model_output_limit` 收尾。流式接收路径只累计
文本并发出 delta；进度检测在步骤完成后进行，不能在该次长响应内部打断重复文本。
本轮 512K 也没有发出 stall warning。因此简单提高输出上限可能只是延长重复，
优先需要针对流内重复和有界恢复设计处理方式。

## 与上下文和缓存的关系

两组都没有触发压缩，也没有记录输入超限、Provider 重试或 Harbor 基础设施异常。
512K 最后一个失败主请求仍命中 207,232 / 208,271 tokens（99.50%）；256K 在
八分钟工具等待后，首请求仍命中 99.51%。**现有证据不支持缓存失效导致这两次任务失败。**

异常结束后的收尾请求命中率低，是先结束、再切换到收尾请求所观测到的额外成本；
它发生在触发时间/输出限制之后，不能倒推成触发失败的原因。

较长历史是否增加重复推理或错误假设持续存在的概率，本轮无法确认。两组实际峰值
都没有达到各自压力目标，每档只有一次，而且走了不同的工具与生成轨迹；不能用
128K 通过、两组失败直接推出大上下文降低能力。

## 建议的处理顺序

1. **修复受管进程取消的有界性**：覆盖后代更换进程组、继承输出管道的情况，限制
   取消后的等待，同时确保不会把仍在运行的后代静默当成已清理。以上本地复现可作为
   后续修复的回归场景。
2. **增加流式重复检测和有界恢复**：检测长周期重复文本；恢复时改变导致重复的状态，
   有限次继续执行。不要仅扩大单次输出配额，也不要无限重试同一请求。
3. **明确最终文件验证**：探针结果、推理中的最佳参数、已保存交付代码要分别记录；
   产物结论以最后一次保存后的实际编译/运行验证为准。
4. 修复运行可靠性后，用相同条件重新比较多次执行。不能把本轮未使用到的 256K/512K
   输入区间补算成已有样本。

本次只新增分析和证据记录，没有修改运行时、延长实验额度或重新运行付费评测。
