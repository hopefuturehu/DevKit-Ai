# 两项 P0 可靠性修复验收

日期：2026-09-14。对应 [具体设计](../designs/task-reliability-recovery-design.md) 中的 P0-A / P0-B。
本轮使用本地进程、确定性 Provider 和原 512K 日志回放；没有重新调用付费模型，
不据此宣称真实任务通过率或缓存命中率已经提高。P1 交付文件验证尚未实施。

## 已实现行为

**P0-A：进程取消有期限。** 流式命令与受管命令共用生命周期，分别接收根进程退出和
管道关闭回调。默认清理总期限 5 秒，TERM / KILL / 排空阶段分别最多 2 / 2 / 1 秒。
进程快照由单个在途后台采集器提供，退出前的旧快照不能证明退出后的进程范围已空。
取消、硬超时和 runtime 关闭共享清理任务，多个进程并行清理。

POSIX 范围包含原 SID 成员和已观察到的后代；子进程 `setpgrp()` 后仍可定位。
每次发信号重核 PID / 启动时间，Linux 支持时使用 pidfd。根退出不等于任务结束。
未清理完成返回 `cleanup_failed`，保留额度和残留身份，工具返回失败，并阻止同批后续操作。
用户取消和全局截止保留原结束原因，附带清理失败信息。
清理记录进入会话事件库，重启时只恢复相同执行环境和系统启动周期的未解决记录。
重试清理可重新核对残留；被提前关闭的旧输出始终保留 `output_complete=false`。

**P0-B：完整性门禁和有限恢复。** 在解析工具参数、写入 assistant 工具消息、执行工具
之前检查响应；主动中断和 `length` / `max_tokens` 会隔离整批正文及工具缓冲，保存为经
redactor 处理的会话 blob。合法 JSON 和同批完整调用也不能绕过门禁。

重复检测只自动干预普通正文。代码围栏、结构化内容和已出现工具调用的响应不触发正文
自动中断；reasoning 仅观测。流显式关闭，关闭最多等 1 秒，无法确认关闭时不发起恢复。
恢复以尾部合成 user 上下文进入历史，明确 `source=runtime`，不冒充用户新任务，
保留 system、工具声明、原输入预算和 thinking 设置。普通 length 耗尽恢复后可做一次
禁用工具的总结；重复停止使用静态摘要，总结自身重复也使用静态摘要。

恢复默认每个 episode 一次、每个任务两次、每阶段 120 秒；与原任务截止取更早值。
首个恢复请求的输出上限取原 cap 和 8192 的较小值。首次有效诊断证据可结束 episode，
计划更新、单纯长文本和任意文件写入不能重置次数。任务次数、阶段截止及费用预留持久化，
与恢复控制消息和审计事件事务提交。resume / 压缩不会清零；调用方显式
`RunRequest(new_task=True)` 或创建新会话才开启新任务预算。

每次真实请求具有 `request_attempt_id`；审计按 ID 合并 started / usage / interrupted /
finished / retry。缺 usage 明确标为 missing，不当成零费用；缓存率仅来自完整已知 usage。
显式费用上限下按输入预算和输出 cap 保守预留，未知请求不释放预留。若未配置输出 cap，
严格费用模式会使用当前输出预留作为实际请求 cap。

## 默认值与启用

进程清理与响应完整性门禁直接生效。按设计保留渐进启用：正文重复检测默认 `observe`，
自动恢复默认关闭。目标任务可以在项目配置中启用：

```toml
[agent.stream_guard]
mode = "enforce"

[agent.recovery]
enabled = true
max_attempts_per_episode = 1
max_attempts_per_task = 2
max_episode_seconds = 120
max_response_output_tokens = 8192
```

未启用恢复时，异常响应依然不会执行任何工具。未改变模型选择或上下文预算。

## 验证证据

原 512K 第 111 步响应共 115,292 字符。离线回放在 **14,156 字符**发现周期 859 的
连续重复，覆盖 5,831 个规范化字符；1 / 137 / 4096 / 整块四种 delta 切分得到相同触发
位置，达到设计的 16K 字符内命中目标。只表示本地可提前中断，不代表远端停止计费。
前 16K 字符已固定为 [回归样本](../../tests/fixtures/reliability/512k-step111-prefix.txt)。

自动化覆盖包括：

- `setpgrp()`、忽略 TERM、根先退出、其他 run 隔离、PID / SID 复用、并发重复取消。
- 清理失败保留额度并可重试；进程枚举停滞仍有期限，且不产生多个在途采集器；UTF-8 分片及管道错误。
- 原日志回放、中文重复；长代码、JSON、变化表格和数字、非重复长文负例。
- 半截 JSON、合法 JSON + length、同批完整与截断调用均执行零次；恢复后的完整调用执行一次。
- 第二次重复停止、有效诊断后第二个 episode、跨 resume 次数及阶段截止、事务失败回滚。
- 缺 usage 保留费用预留并跨 resume 生效、审计请求去重、流关闭期限、总结重复不再恢复。
- 现有 Agent、Provider、会话存储、CLI、Web、Skill 和子 Agent 集成回归。

完整 Python 回归：**638 通过、10 跳过**。Web 事件回放：**8 通过**。
修改文件的 Ruff 检查与 `git diff --check` 通过。

## 能力边界

本机验证环境为 macOS / Python 3.14。POSIX 轮询后端返回 `observed_empty`，不声称 cgroup
级隔离；两次观察间完全脱离 SID 并重新归属的后代仍可能逃逸。Windows 标记 `root_only`，
Linux pidfd 分支和 Windows 后端仍需要对应平台 CI。硬清理失败、权限不足或管道不完整
会明确显示，不能用根进程 returncode 替代清理证明。

首版检测针对精确周期重复，语义近似循环可能漏报；合法重复散文也可能触发，因此默认
仍为 observe。真实任务效果需要后续固定配置的多次对照，单条故障回放不替代该评估。
