## 已落地的行为

| 调整 | 当前实现 | 直接效果 |
|---|---|---|
| 稳定证据 | 命令终态/退出码及 stdout、stderr 摘要排除进程 UUID、耗时；摘要覆盖累计保留输出 | 新进程与后续轮询消费不会把同一结果变成新证据 |
| 新证据进展 | 重复弱证据不再抵扣停滞；执行成功不自动当作强进展 | 停滞计数能反映重复探索 |
| 独立检测 | 参数规范化、非幂等命令检测、相关资源失效、v2 checkpoint、有限容量 | 改等待参数、无关强进展、压缩和 resume 不能清空已识别限制 |
| 执行前限制 | 先验证参数/权限，再检查重复限制；允许有效新操作并在完整批次后决定收尾 | 限制实际调用，保持工具协议配对和可恢复结果 |

首版强制适配覆盖命令、shell、文件读取、文本搜索、终态进程轮询和外置上下文读取。
其他工具参与进展监控，尚未自动接入新的执行前限制。存活进程继续作为 `WAITING`；
`wait_seconds=0` 启动后不主动轮询，运行器也会在后续启动前观察已完成进程的累计证据。

权限拒绝、参数错误或不完整结果不能替换已经建立限制的完整证据。读取遇到外部文件修改
时检查当前内容版本，相关 `apply_patch` 会使文件及对应搜索范围的旧观察失效。

## 自动化验证

执行入口：

```bash
.venv/bin/pytest -q --junitxml=artifacts/repeat-guard-validation-20260913/pytest.xml
```

| 测试文件 | 通过数 | 覆盖重点 |
|---|---:|---|

| `test_repeat_identity.py` | 18 | 规范化、周期、跨目标状态、迁移、一次回读凭据、容量与额度 |
| `test_execution_tools_policy.py` | 33 | 真实进程、退出状态、累计摘要、受管/非受管一致性、生命周期 |
| `test_agent_loop.py` | 76 | 执行前拒绝、审批、批次配对、恢复、压缩、预算和完整模型循环 |

典型强制模式夹具固定五个重复请求：前三次执行，后两次拒绝，再最多一次模型收尾。
固定输出、空输出和固定失败分别覆盖 `run_command`、`run_shell`。断言检查真实
`start_process()` 次数、`tool.started` 事件和每个 tool call 对应的 result，不只检查文字提示。

另外验证了以下边界：

- 同一响应请求六个重复工具：只有三个实际执行，六个结果完整交付，下一次新操作可继续。
- 不同文件、区间、目标、环境或查询范围不会合并；相关文件更新后能读到新内容。
- 外部修改与 `apply_patch` 修改都允许文件回读；明确额度下五次静默写入实际完成。
- 真实发布压缩摘要后，独立限制保持不变，必要回读一次成功，再次重复仍会受限。
- 重建 Agent/执行目标并 resume 后，受限命令不会重新启动。
- 改用被权限策略拒绝的 shell 调用形式，不能清掉原 shell 操作的限制。
- 外置上下文重复读取可受限；复用限制状态也不能越过其他 session 的 blob 授权。
- 三个零等待启动完成后，即使模型不调用 `poll_process`，后续重复启动仍受限。
- 输出截断不单凭相同前缀触发新的执行前阻断；进程增量输出消费不改变累计结果身份。

跳过项为 7 个需要显式启用 Docker 的判分隔离测试和 3 个需显式启用的大规模 soak 测试。
本次未修改对应判分容器实现，也未把跳过计为通过。测试期间有一条既有 Starlette/httpx
弃用提示，没有测试失败。Ruff 检查及 Git 差异检查通过。

## 真实模型续跑

使用 `scripts/validate_repeat_guard_live.py`，固定 `deepseek-v4-flash`、temperature=0、
thinking=disabled、输出上限 512。两种模式各两场，第二轮交换执行顺序。

每场前四个模型响应由脚本固定为读取同一干扰文件，但工具真实执行。之后交给真实模型，
目标是读取另一个文件中的校验码，最终只返回校验码。通过标准为最终文本与文件校验码完全
一致；没有让模型自行判分。

| 模式 | 完成数 | 每场干扰文件 Tool 执行数 | 每场被拒绝调用 | 每场真实模型请求数 | 两场估算费用合计 |
|---|---|---:|---:|---:|---:|
| observe | 2/2 | 4 | 0 | 2 | $0.008286 |
| enforce | 2/2 | 3 | 1 | 2 | $0.008525 |

这证明在该夹具中，限制提示没有妨碍模型换路线完成任务。强制模式提示增加了少量输入，
估算费用略高，不能声称节省了整体模型费用。文件版本预检查仍会访问文件，所以正式 Tool
执行数减少也不等价于底层文件读取 I/O 次数减少。

共 8 个真实模型请求；按配置的输入 $1/百万、输出 $2/百万估算为 $0.016811。
每次请求前按输入预算和最大输出保守预留，累计预留 $0.088192，低于设定的 $0.10 上限。
这些费率来自本地配置，不是实时价格核验或账单。首次沙箱联网尝试连接失败，获准联网后
完成上述四场；失败尝试与成功场次的本地产物分别保留，没有把连接失败当成模型行为失败。

本组是人为固定重复前缀后的小任务续跑，不是模型自然进入循环的发生率实验，也不是
`path-tracing-reverse` 或其他公开基准的整题复测。

## 开销与边界

本机对 128 条活跃限制做 2,000 次规范化与内存查找测量：中位 2.542 微秒，P95 2.667 微秒。
该夹具的独立重复 checkpoint JSON 为 37,950 bytes。此微基准不包括文件版本读取、后台
进程扫描、checkpoint 写入或模型调用，不能当作每轮完整防护开销。

当前保持 `observe` 默认值。启用强制模式：

```toml
[agent.progress]
repeat_guard_mode = "enforce"
```

相同输出仍不能证明没有副作用。静默消费队列、迁移等任务应给出宿主控制的重复额度；
任意 shell 等价判断、未知工具的强制适配、单个模型输出内部的超长参数重复，以及
公开基准完整任务成功率和大规模误拦率，仍不在本次已验证结论内。
