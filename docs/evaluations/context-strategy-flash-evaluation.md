日期：2026-09-13。任务为 `path-tracing-reverse`。本轮统一使用 `deepseek-v4-flash`，
主请求单次输出上限 32,768；从四个独立任务环境完整执行，随后运行官方验收。
运行代码冻结在 `99d70d8`，包括之前的标题兼容修复和双路径事实保留提示。
本轮只扩展评测入口与只读审计，没有修改压缩器或中途修补进展控制器。

后续已完成每组累计三次的[完整复测](context-strategy-flash-repeats.md)，包含环境异常排除、
CURRENT 替补和全部费用。下面保留首轮结果，选型应同时参考复测数据。

**本轮双路径是唯一官方 3/3 且正常交付的方案，费用比 CURRENT 这条轨迹低 21.73%。
优先继续验证双路径，保留 CURRENT 默认，B 暂缓投入。** 每组一次且压缩前轨迹已经不同，
不能把结果直接归因于摘要改动，也不能将 21.73% 写成稳定节省率。A 的摘要最便宜，但

## 四个实现与统一条件

| 名称 | 实际自动压缩行为 |
|---|---|
| CURRENT | 原有独立摘要服务，摘要输入预算 60K，沿用分段、重试、格式修复和缩短流程 |
| A | 在当前完整请求后追加旧摘要指令，保留工具定义；摘要生成额度改为 8K，最多尝试两次 |
| B | 后台按默认 24K 叶子预算生成摘要，压力触发时补齐并合并，只发布根摘要 |
| 双路径 `a_fallback` | 复用真实出站前缀，追加强化的交接规则；前缀尝试一次，失败后以专用 system 和 JSON 历史、无工具的独立请求兜底一次 |

四份配置仅策略字段不同，主模型和摘要模型均显式指定 Flash，temperature=0、
thinking=disabled。软件窗口 131,072，输入硬配置 120,000，主输出预留 32,768，
安全与协议各预留 2,048，因此主输入预算 94,208，压力线约 75,366。A/B/双路径
按完整续跑请求检查 40K 低水位；最近历史目标 20K，摘要正文目标 3K、硬上限 4K。

“统一 32K”指主请求输出额度。CURRENT/A/B 的摘要生成额度为 8,192，双路径前缀
继承 32,768，独立兜底为 8,192；这些属于被比较实现的现有差异，不能声称所有摘要
请求参数完全相同。4K 正文门禁使用文本启发式估计，与 API completion_tokens 不同。

每组最多 240 步、Worker 1,740 秒，最终模型收尾最多 30 秒，官方 Agent 超时 1,800 秒。
保守预算 $10/组，按未命中输入费率控制；费用结果另按真实缓存分桶重算。关闭 Skill、
子 Agent、公共记忆。固定随机种子 20260910，串行顺序 B → 双路径 → A → CURRENT。
不人为预热；服务端跨组缓存和模型响应随机性仍是混杂因素。官方测试和题解未注入运行中的模型。

## 任务停滞与摘要正确性

B 完整执行 240 步，却只出现 8 种工具调用签名；同一 `strings | grep ... | head -80`
命令执行 235 次，235 次成功返回同一个输出引用，进程 ID 各不相同。循环约从第 6 步
开始，首次压缩之后的主响应是第 53 步，因此不能将循环起因归于首次摘要丢失信息。
六份已发布根均保留“停止重复同一 strings 命令”和“尚未编写 mystery.c”，模型仍继续
重复。这说明记录失败尝试并不自动保证主模型采纳纠偏。

A 的四次压缩全部成功，但第 88 步主模型生成 77,153 字符正文、没有工具调用，
`finish_reason=length`，输出 tokens 恰为 32,768。后半段持续重复寄存器布局推断，
随后被运行器终止，最终没有创建源码。这里应区分单次生成失控与多次工具循环。
提高上限没有消除这种退化；双路径也在第 6 步出现一次 32K 无效工具参数输出，
工具 schema 拒绝后模型自行改写命令继续。那一次没有执行损坏命令，费用已计入。

CURRENT 同样在第 88 步输出 32,768 tokens、没有工具调用后被终止，正文 56,453 字符，
末段退化成连续的 “Hmm”。这与它七次摘要均成功同时成立。

公共进展控制器中，`_process_progress` 将进程 ID 放入完成结果的 evidence_key；
`observe_tool` 优先用该键生成结果指纹，导致相同命令和输出被视为不同结果，无法匹配
工具循环。`run_shell` 没有标成幂等，另一重复检测也不适用。`finish_step` 对 weak
步骤减少而不是增加 no_progress_steps。B 的 240 个标签全为 weak、全部 continue，
停滞计数始终为零，与该代码路径一致。

只读反事实回放将相同输出键中的进程 ID 去除：原指纹下 235 次都 continue，稳定键下
第 2 次 warn、第 3 次 recover，继续喂入相同结果则第 6 次 finalize。这只验证控制器
检测机制，没有实际执行恢复模型，不能把它写成任务通过或已经节约的费用。本轮运行
不采用该修改，保持四组同一代码。

摘要来源哈希、父版本链、真实用户锚点、单一活动根及 B 节点来源可以机械核验；这些
验证覆盖和发布一致性，不证明每条自然语言结论都正确。最终任务验收单独报告。

双路径第四份摘要（覆盖 1–130）仍将旧猜测“球心 (-5,1,0)、半径 0.5”与“实测球体匹配”
联系在一起，虽然保留了寄存器歧义的限定。其覆盖范围内消息 97 生成的临时代码已经改用
`SC={0,-0.5f,-5}; SR=1.0f`，消息 98 返回的是该新候选的图像比对结果。这里仍存在旧
推断与新版本试验错配，不能因结尾留有“存疑”就当作事实正确。最终代码使用正确参数并
通过官方检查，但没有证明四件最小改动消除了摘要错误。此为单项定向抽查，不计算泛化
事实准确率；原文位置、摘要摘录及哈希保存在诊断 JSON。

## 评估与下一步

1. **双路径是本轮最值得继续验证的候选。** 它确实挽救了两个真实超长事件，并在连续压缩后
   正常交付。保留前缀优先和一次兜底结构；暂不据单次成功更换生产默认。
2. **A 保留作低开销对照，B 暂缓。** A 98.19% 的摘要命中和 $0.026069 费用说明前缀复用
   有实际价值；主模型退化使本次任务失败。B 全程缓存最高，但由大量重复请求贡献，
   本次没有得到足以补偿后台叶子、合并和未用节点开销的任务收益；也不能断言循环由 B 引起。
3. **下一步先处理两个具体问题。** 一是同参同输出的循环识别排除进程 ID 等易变信息，
   单次流式生成的明显重复另外检测；不能靠继续扩大输出上限。二是复用这次三个超长断点，
   对比当前完整独立重总结与只缩短超长候选的费用/信息保留，仍保持最多一次兜底。
   缩短候选只处理长度，不会自动纠正旧错误；本轮没有实现或测试这条新优化。
4. **补最少的确认性测试。** 对当前方案与双路径各再做两次同预算完整运行，使每组至少
   三次；把已保存的错误球体参数案例做同断点短续跑，验收正确版本是否保留、是否重走
   错误路线。观察典型 thinking/Skill 设置后再扩旧 18 题，避免把主模型退化误归为压缩缺陷。

新增内容规则可能促使摘要保留更多材料，但本轮没有对相同输入单独消融提示词，不能
认定它就是超长的原因。两条路径本来已包含 3K 目标、4K 上限指令；问题不能归结为
“忘了告诉模型长度限制”。结构校验、事实保留与最终任务验收必须分别评价。

与历史 Pro A32/双路径的结果分别报告。模型、运行轨迹及实现版本不同，不能把本轮
Flash 的成本差直接归因于摘要改动，也不能将历史单次 3/3 当作此次同条件对照。
