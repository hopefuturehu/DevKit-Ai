# CURRENT / A / B 真实任务原型与评测

日期：2026-09-10。任务：`path-tracing-reverse`。真实结果尚待运行，不引用旧 L1 的
证据问答成绩作为本次完整任务成绩。

## 实现范围

三组使用同一 `AgentRunner`、工具执行器、上下文装箱、持久化和 Harbor 官方验收。
`context.compaction_strategy` 默认为 `current`，A/B 显式开启。

| 策略 | 自动压力压缩路径 |
|---|---|
| CURRENT | 现有 `ContextCompactor`，60K 摘要输入预算及原有分段、修复机制 |
| A | 复制本轮完整请求的消息与工具定义，尾部追加摘要指令；输入上限按主窗口减输出及安全预留计算；生成一次候选后检查完整续跑请求，合格才发布 |
| B | 后台处理闭合、不可变的历史块；默认每叶 24K 输入，四路预算受限递归合并；触发压力后补齐范围、合并并一次发布根摘要 |

A/B 都保留原始消息，发布沿用数据库父版本 CAS。B 的中间节点保存来源范围、摘要、
原文哈希和子节点引用，不改变主模型上下文；只有根摘要发布时切换。
连续压缩时合并上次根摘要与新增叶子，检查完整覆盖，不静默跳过超大工具原子组。
后台最多一个请求流，与主请求并行；结束时取消并等待，已完成 usage 纳入任务累计费用。
生成最多两次尝试；失败遵循已有压缩退避配置。

这仍是原型：B 的节点文件持久化，但进程重启后不恢复内存索引，会重建未发布的节点；
单个工具原子组大于叶子预算会明确拒绝，还没有更细的安全分割；未增加模型自行交接工具。
手动 `/compact` 仍走原有服务。本次只比较真实 Run 的自动压力压缩。
A 保留组装前缀以争取缓存复用，但实际命中必须由 Provider usage 验证。

## Skill 恢复对 A 的影响

history 布局中，当前 Run 绑定的完整 Skill 如果不在保留尾部，会从绑定的原版 blob
恢复为尾部合成消息；仍在尾部则复用，不要求模型重新读取。相同版本和游标上的恢复幂等。
未消费的已交付资源也会恢复；正文绑定持续整个 Run，不会因模型完成一个阶段自动卸载。

A/B 发布前先预览这些恢复消息，不写历史，再对以下完整请求计数：

```text
压缩后输入 = 固定提示与工具 + 摘要与用户锚点 + 保留历史 + 缺失的必要 Skill/资源
净释放 = 压缩前完整输入 - 压缩后完整输入
```

恢复后超过低水位或没有净释放即拒绝发布，旧投影保留。默认低水位 40K、
Skill 正文预算 16K，但这不是 16K 的免费区间；大 Skill 会直接挤占续跑空间。
预览和实际恢复均检查原版 blob 的长度及哈希，合成正文不能成为真实用户锚点。
正文恢复本身无模型请求，但 A 的摘要输入可能已包含它，随后续跑又会携带原文，不能把
全文大小当成永久释放量。追加到尾部不主动重排原有前缀；A 发布新摘要时改变的前缀
仍可能使后续历史缓存失效，不能将这种损失全部归因于恢复，也不能保证缓存全保留。

## 冻结评测协议

入口：[运行脚本](../scripts/run_context_strategy_task.py)。先生成配置、wheel、哈希清单与
固定随机顺序，再用 `--run` 串行执行。原始事件、SQLite、模型结果和官方验收均保留。
三个配置只有 `compaction_strategy` 不同，使用相同的冻结 wheel 和任务文件。

- 模型 `deepseek-v4-pro`，temperature=0，thinking=disabled，主输出上限 8192。
- 软件窗口 131072，输入硬配置 120000，压力阈值 0.8；A/B 完整请求低水位 40000。
- 最近历史 20000，摘要正文上限 4000，摘要请求输出上限 8192，B 叶子输入 24000。
- 每组 240 步，Worker 墙钟 1740 秒，收尾模型超时 30 秒；官方 Agent 超时 1800 秒。
- 每组保守费用预算 10 美元；预算仍按统一未命中输入费率控制，实际费用另用原始缓存分桶重算。
- 关闭子 Agent、公共记忆和 Skill；Skill 正确性由独立真实 Runner 回归覆盖。
- 不人为预热，不共享可写任务目录；Provider 跨组缓存影响仍可能存在。

如果某组没有触发压缩，必须记为覆盖不足，不能把无压缩运行当作压缩收益证明。
较低共同输入预算的补充实验要单独标为压力实验，保留所有原始轮次。
一次任务、每组一次只能作选型先导，不能据此估计稳定提升比例。

## 输入计数与计费

Pro 官方固定版本的 tokenizer、encoder 与已校验 Flash 资产逐字节相同，新增 Pro
映射后共享本地资产，记录各自模型版本。离线 tokenizer 经 SHA256 检查后随任务安装，
请求过程中不下载。来源：[官方 Pro 仓库](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro/tree/b5968e9190ef611bbf34a7229255be88a0e937c1)。

三次独立真实 Pro 请求的预测/API 输入为 **310/310、7510/7510、24610/24610**。
这验证了该模型的本次 chat 序列化，不证明所有工具布局、reasoning 模式都零误差。

实际成本使用每请求原始 `hit`、`miss`、`output`，含后台叶子、合并、失败重试和收尾；
不重复累加用于预算的聚合 `model.usage` 压缩事件。缺 usage 记未核实，不按零费用处理。
价格以执行时冻结的[官方定价](https://api-docs.deepseek.com/quick_start/pricing/)为准，
峰谷时段分别计算；并报告统一峰值费率的标准化成本，避免执行时段混淆策略比较。
