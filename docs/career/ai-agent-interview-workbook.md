# AI Agent 面试答题与批改工作簿

> 创建日期：2026-09-15。出题依据：胡杨的 Agent 岗位简历与 bot 仓库，代码核对基线 `745ad3c`。
> 面向 Agent / 大模型应用研发岗位，共 24 道核心题、6 道扩展题。重点是上下文、Runtime、工具、记忆、可靠性、多 Agent 与评测。
> 题目是根据简历与实现推导的练习题，不代表某家公司实际题库。个人贡献、业务效果和 KAT 经历由答题者按实际情况补充。

## 使用方式

1. 建议每次回答 3–5 题，先写“我的回答”，主回答按面试口述约 2–3 分钟组织，再补充追问。
2. 可以写伪代码、数据流或真实故障案例；暂时不会的部分直接写“不确定”，便于针对性补齐。
3. 保存文件后，在当前对话中发送：**“我已回答 Q01–Q05，请读取工作簿并批改。”** 替换为实际题号即可。
4. Codex 读取已保存的回答，在对应“Codex 指正”区写反馈，保留“我的回答”原文。需要进一步了解个人经历时，写明缺少的信息。
5. 在“我的修订”中改答，保存后发送：**“请复评 Q01–Q05 的修订。”** 复评反馈追加到该题批改区。

### 批改约定

每题反馈按以下顺序组织，内容短时可以合并：

- **总体判断**：需要补充 / 基本清楚 / 可应对深入追问，并解释原因。
- **技术指正**：引用原回答中的具体说法，说明错误或不严谨之处；涉及当前实现时给出文件依据。
- **遗漏与证据**：指出尚未解释的机制、异常路径、指标口径和个人贡献边界。
- **表达改进**：给出更清晰的回答结构或局部改写；不能补造工作经历、实现能力和业务指标。
- **下一层追问**：根据本题回答继续提出 1–2 个问题，不机械重复原追问。

判断正确性优先于术语数量。设计题允许合理的不同方案，但要说明前提、取舍和验证办法。历史实验与当前实现分别核对，不能把方案设想当成已经落地的经历。
