# A+D 主动交接与容量压缩收益测试方案

> 状态：2026-09-10 已完成 L0 和 L1 受控实验；L0 37/37，L1 36/36 个片段、288 个检查已执行。
> 详见[完整量化结果](context-handoff-l0-l1-results.md)，包含失败、未知费用和缓存复用限制。L2/L3 未运行。
> A/D 的定义见[重设计候选](context-compaction-redesign-options.md#7-当前优先候选d-主动交接a-按容量兜底)，生产默认入口尚未改成 AD。

## 1. 要回答的问题和现有证据边界

优先回答三个问题：A+D 相对现有实现是否改善有效交付及总费用；相对纯 A，主动交接 D 是否有
额外收益；短任务是否为了交接工具、提示和不必要的上下文切换付出额外成本。

此前主样本 18 题没有触发摘要压缩，压缩成功率为 N/A；补充运行只有两次摘要安装，安装成功
2/2，但下一次主请求成功只有 1/2。SymPy 相邻主请求输入观测减少 71.65%，不能替代整题净收益。
样本与统计边界见[18 题上下文分析](public-benchmark-context-analysis.md#3-压缩主样本未覆盖补充运行有两次)。
因此必须同时安排普通任务回归、长任务专项和固定状态对照，不能只重跑旧 18 题或只测摘要变短。

以下样本数和验收阈值是原预注册建议，实际执行覆盖以结果文档为准，不是已取得的成绩或统计功效保证。先导完成后可调整
正式设计，但须在正式集运行前冻结；不能看到正式结果后改变门槛。

## 2. 对照组和共同条件

| 组名 | 策略 | 回答的问题 |
|---|---|---|
| CURRENT | 保留现有范围选择、摘要预算及自动触发策略 | 相对项目现状是否值得更换 |
| A | 仅运行器按容量触发大范围摘要 | 大范围压缩本身的效果 |
| D | 仅模型主动提交交接包；安全预算检查仍生效，超限时保存状态并停止 | 主动交接的收益与漏触发风险 |
| AD | 有效主动交接优先，没有及时交接则运行 A | 组合是否比纯 A 更好 |

D 组不能悄悄使用 A 或另一种摘要兜底，否则它已经是 AD；但不允许为了实验绕过硬预算发送非法
请求。其漏触发导致的停止计为失败。A 与 AD 使用相同的 A 实现、容量阈值、摘要预算和发布器。

所有组固定主模型及 Provider、模型版本信息、主推理设置、任务起点、镜像 digest、工具权限、
源头限量/外置/检索策略、总步骤/时间/费用预算。CURRENT 的专有摘要配置单独记录，A/D 的生成
方式差异属于处理策略的一部分。任务预算不能在交接后重置，也不能给 AD 更长时间来获得优势。

已知协议问题必须作为共同修复进入所有组。例如若旧 checkpoint 仍造成 `reasoning_content`
HTTP 400，应先共同修复和验证，再比较压缩策略；历史有缺陷版本只作历史参照。不能让 AD 独享
协议修复后，把修复收益都算成主动交接收益。

工具定义和策略指令在各组运行内保持稳定。组间新增交接 schema、提示等开销属于实际功能成本，
应计入整题比较；专门的缓存机制实验另行控制共同前缀，不用修改 system 的方式反复提醒交接。

## 3. 分阶段执行

| 阶段 | 建议规模 | 产出与进入下一阶段的条件 |
|---|---|---|
| L0 离线正确性 | 下述 12 类场景，覆盖适用入口和事件发生位置 | 所有不变量通过，无模型费用 |
| L1 固定状态机制对照 | 6 个 checkpoint × CURRENT/A/强制 D × 2 次 = 36 个续跑片段 | 容量、保真、首个工具协议和缓存曲线可解释 |
| L2 自主行为先导 | 6 个完整任务 × CURRENT/A/D/AD × 2 次 = 48 个运行 | 确认模型会自主交接，估算费用，冻结正式参数 |
| L3 正式回归 | 原冻结 40 题 × CURRENT/A/AD × 3 次 = 360 个运行 | 普通工作负载上的交付、费用和延迟对照 |
| L3 长任务专项 | 12 个未用于调参的长任务 × A/AD × 3 次 = 72 个运行 | 在高压力和多次切换下检验 D 的增量价值 |

这是逐级筛选，不是一开始就启动全部付费运行。可先从 L1 中两个 checkpoint 各一轮开始；如果
协议或保真失败，修复后再继续。L2 的纯 D 用于诊断，正式轮重点比较 CURRENT、A、AD。

### L0：故障和时序矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 1. 模型一直不交接 | AD 到阈值启动 A；D 安全停止，均不越过发送预算 |
| 2. 模型连续无效交接 | 延后重复候选；硬压力不被冷却期阻挡，无无限循环 |
| 3. 正常自然交接 | D 候选直接发布，不额外重复生成 A 摘要 |
| 4. D 工具参数输出截断 | 不执行半个调用，不覆盖旧状态，恢复有次数和费用上限 |
| 5. A 空输出、格式不合格或长度截断 | 分别记录失败原因；不能把截断正文安装为成功摘要 |
| 6. 摘要请求输入超限、单条工具结果巨大 | 先预算检查或有界恢复；不能静默漏掉未覆盖原文 |
| 7. 传输中断、限流、永久鉴权失败 | 区分可重试与永久错误，次数/时间/费用均受限 |
| 8. 同一响应同时包含交接和普通工具 | 完成或明确终止普通工具链后切换，调用与结果闭合 |
| 9. 交接生成期间到达用户更正 | 发布前/后两个时点均测试，新要求保留，旧结论不得覆盖它 |
| 10. 文件改变使证据过期 | 识别旧版本引用，重建或要求重新验证 |
| 11. 发布时崩溃或重复回调 | 恢复后最多一个活动版本，不漏消息、不重复执行副作用 |
| 12. 摘要合格但完整请求仍高压 | 记录未达低水位及原因，不无限压缩固定前缀或巨大尾部 |

共同不变量：原始记录可恢复、范围与版本一致、用户约束及更正可追踪、总预算连续、工具协议
合法、失败不破坏有效旧状态。故障注入验证运行器行为，不代表真实模型发生这些行为的概率。

### L1：相同起点，隔离一次切换的作用

六个 checkpoint 覆盖：短历史、明确阶段边界、连续推理中途、接近安全输入预算、跨区间更正、
大工具结果与必要尾部。优先纳入已有 Chess/SymPy 压缩前保存状态；不足部分使用具有可验证
事实和实际依赖关系的 fixture，分别标明真实历史与合成来源。

每份 checkpoint 冻结消息、工具/指令、工作区快照、引用产物、当前任务和源范围 hash。三组从
相同状态分叉：CURRENT 按旧算法处理，A 生成大范围摘要，强制 D 要求模型提交交接包。
两次重复保留原始结果；六种覆盖不等于六个独立真实业务来源。

强制 D 是测交接内容和协议的实验措施，不能用来证明模型会自主选择时机。AD 不需要在此重复
一套摘要算法，其两个入口和去重在 L0 验证，自主触发在 L2/L3 验证。

每个片段继续完成相同的 8 个逻辑检查点，包含约束应用、最新事实、失效证据、未完成动作、
引用回读和至少一次真实 Provider 工具调用往返。工具使用可恢复的隔离 fixture；允许模型在
检查点内额外检索，记录这些实际请求与费用。检查点相同不要求模型输出或请求次数相同。

容量差先在同一状态离线组装：除候选替换外固定全部内容，计算完整请求前后差。随后真实发送
验证实际 usage，不能把估算 token 冒充 Provider 实测，也不能把不同请求中的状态增长算成
纯压缩收益。只在原请求能发送的片段增加无压缩参考组，其费用和样本数另列。

每个检查点由评测侧提供隐藏答案或验收规则；不是仅检查摘要是否包含 `F01` 等标记。正确性
至少包括：原用户硬约束、最新更正、事实与假设区分、未完成事项、证据版本及下一步可执行性。
“测试已经通过”必须与相应版本的真实结果一致。模型自评不能作为唯一评分器。

### L2/L3：让 Agent 自己执行任务

L2 使用两道短任务、两道具有自然阶段的任务、两道持续增长的长任务。先导使用独立开发 fixture，
不从正式长任务集中挑选成功样本；任务从统一干净起点运行到官方/确定性验收或预算停止。
任务题面不写“第 N 步调用交接”；只有正常的工具说明和策略提示。记录 D 何时调用、为什么
延后、A 何时兜底，并人工复核所有异常切换。

L3 普通回归沿用[冻结 40 题清单](../evals/public-regression-40-v1.json)，保留未触发压缩的题。
这是已研究过部分样本的固定回归集，不宣称是全新的盲测集。不得按本轮得分换题；外部环境
故障独立列账，按预注册规则补跑整组成对样本，原运行和费用仍保留。

正式长任务专项至少覆盖三个有实质依赖的阶段、早期约束在后期生效、修改后需重新验证、失败
尝试不能重复、用户中途更正，以及连续工作可能经历两次以上切换。优先自然产生代码/日志/
数据处理历史；复制无意义文本只能作为容量压力测试，不能当真实任务收益。

按任务定义和开发基线划分短/阶段/压力桶，在运行 AD 前冻结。若某桶实际未发生交接，报告
覆盖不足；不能事后只保留触发过交接或获胜的题。低阈值诱发切换可以另作机制实验，但正式
收益必须使用冻结的拟部署阈值。每轮切换后的完整输入目标也必须共同固定。

对同一 task/repeat 的策略顺序随机、交错执行，并记录时间段和并发度；固定网络和工具资源
限制。Provider 支持 seed 时记录，但不把 seed 当成确定性保证。公共长期记忆、工作目录、
进程和可写产物按运行隔离，避免前一组的答案影响后一组。

## 4. 指标与计费口径

### 4.1 主要终点

| 指标 | 定义与用途 |
|---|---|
| 产物通过率 | 官方/确定性判分通过数 ÷ 计划中已完成评估的运行数 |
| 有效交付率 | 产物通过且运行正常完成的数量 ÷ 同一运行数；协议崩溃但补丁通过另列 |
| 每次有效交付费用 | 该策略全部运行费用（含失败）÷ 该策略有效交付次数；零交付时记不可定义，不能写零 |
| 每题平均费用 | 同一冻结任务集合的全部费用 ÷ 运行数；必须同时展示交付率和预算停止率 |
| 完成耗时 | 整题墙钟、模型总等待、交接阻塞分别统计；失败耗时及工具耗时另列 |

用户中止、批次预算提前终止、外部环境故障、缺 usage 都单列。尚未执行的题不能计成功或模型
失败；主表报告计划/已开始/已判分的数量。不同完成覆盖、廉价早停或高失败率不能被解释为省钱。
若给出仅成功任务耗时，必须同时提供失败数和停止时间，不能靠删去失败运行改善 p95。

成本在所有模型请求上求和，包含正常推理、D 的交接输出、A 摘要、repair/condense/重试、检索
后续推理、压缩后第一请求、终止收尾和已发出但稍后才返回的请求。D 已包含在某条主响应中时
只计一次；费用不能同时算入主响应和“交接调用”。真实工具/容器费用如可测，单独列示。

对具有互斥缓存命中/未命中输入计费桶的 Provider：

```text
request_cost = (hit_tokens × hit_price + miss_tokens × miss_price
                + billed_output_tokens × output_price) / 1_000_000
```

有独立 cache-write 或其他计费项时按相应规则加入，不能与已包含它们的 input 再次相加。执行时
记录端点、模型、价格生效日期和计费定义，优先与账单对账。reasoning 已包含在 billed output
中时不重复收费；缺 usage 的失败请求保留未核实费用，不以零填补。

当前 `AgentRunner._calculate_cost()` 按 input/output 两个统一费率计算，未区分缓存读写价格；
`cost_usd` 不能直接作为这轮缓存净收益的账单真值。需用保存的 `raw_usage` 重算并对账；预算
控制可保留保守估算，报告同时区分估算费用和按计费规则重算费用。

### 4.2 解释收益的次要指标

| 指标 | 口径 |
|---|---|
| 缓存命中率 | 有完整 usage 的请求中 `Σ hit / Σ input`；同时给出覆盖率，分主推理/摘要/恢复/收尾 |
| 固定状态释放量 | 相同 source_version 下 `完整请求 before − after`，记录估算器和真实核对值 |
| 整题累计输入 | 所有主请求和辅助请求的实际输入之和，不能只累加压缩后的主请求 |
| 候选成功率 | 合格候选数 ÷ 已结束生成尝试数；D/A 分列，重试也单列 |
| 发布成功率 | 实际发布数 ÷ 发起发布数；另报触发后最终发布数 ÷ 已结束触发流程数 |
| 首次续跑成功率 | 下一主请求成功并完成其必要工具往返的发布数 ÷ 应当续跑的发布数 |
| 事实保真 | 隐藏检查项通过数/总数；硬约束、更新事实、假设混淆和证据过期分别统计 |
| 连续推进 | 切换后到下次切换/结束的逻辑检查点、有效动作、重复失败动作数 |
| 无效切换 | 无任务进展又切换、未达低水位、立即再次超压，分别计数 |
| 回本位置 | 相同后续逻辑检查点上累计费用首次低于对照的位置，并检查到终点是否保持 |

请求成功不等于任务推进；HTTP 200、工具返回成功、摘要有固定标题都不能单独计作有效交付。
未尝试的成功率为 N/A；候选失败但经恢复发布成功，同时保留候选失败和最终恢复成功两个事实。

## 5. 缓存实验与因果归因

L1 分别记录摘要请求及切换后第 1/2/3/5/8 个逻辑检查点的 hit/miss、输入量、费用与等待时间。
不同候选可能导致更多检索，因此同时给出每个检查点实际请求数，不以 API 请求序号强行对齐
任务进展。8 个检查点内没有回本就记“未观察到”，不能外推成已经回本。

控制缓存起点：独立副本在最前可控前缀中使用等长、固定的试验标识，运行过程中不改变；必要
时对每个副本执行相同的预热步骤。通过实际 usage 验证状态，不能假设服务端缓存已清空或必然
命中。预热开销在 L1 实验账单中单列；模拟已有热历史的机制比较可以从预热后起算，但要同时
展示包含预热的总费用。L2/L3 从任务开始计费，不排除首次请求成本，也不人工预热。

跨组共享缓存、首请求已高命中、缺 usage 或执行顺序不平衡均应在报告标注。无法隔离时只能
报告该运行环境下的费用差，不能声称精确测得冷缓存或前缀设计的独立贡献。

缓存重建成本已经包含在切换后的请求费用中，不能再额外加一次。只有固定状态/后续工作量
的对照才估计切换重建的增量；自由运行轨迹不能给出精确的单次压缩回本轮数。

整题至少给出三组比较：AD 对 CURRENT 的升级净效果、A 对 CURRENT 的大范围摘要效果、AD
对 A 的主动交接增量。若只发现 A 有收益而 AD 没有额外收益，应选择纯 A 或继续调整 D；不能
把 A 的收益重复包装成 A+D 的独有收益。

## 6. 验收与统计决策

建议预注册以下正式验收门槛，先导只用于筛选和估算，不宣称已证明总体可靠性：

| 项目 | 建议判据 |
|---|---|
| 运行器硬门禁 | L0 不变量全部通过；正式样本零已确认的新消息丢失、重复副作用或交接协议错误 |
| 质量 | AD 相对 A、CURRENT 的有效交付率差值的 95% 区间下界均高于 −5 个百分点；硬约束错误逐例审查 |
| 成本收益 | 长任务 AD 相对 A 的每次有效交付费用点估计至少下降 10%，且区间支持费用下降 |
| 短任务开销 | 相对 CURRENT 的每题费用点估计不增加超过 5%，同时给区间和是否无谓交接 |
| 时延 | 完整交付墙钟 p95 不回退超过 10%；不足以稳定估计 p95 时不给“时延无回退”结论 |

10%/5%/−5 个百分点是工程取舍建议，不来自历史结果，也不是预期收益。若成本无下降但有效
交付率提高，应作为“可靠性改善、增加多少费用”的另一条结果报告，不强行判成省钱成功。

以 task 为配对和重采样单位，同一题所有策略和重复整体保留；采用分桶的配对 bootstrap 给出
95% 区间。报告各题差、题目等权汇总和合计费用，普通 40 题与长任务专项分别展示。正式运行
次数多不等于独立题目多，不能把 40 题 × 3 次当成 120 个独立任务，也不能把一次运行中数百个
请求当独立样本来缩窄区间。

质量数据很稀疏或所有配对结果相同时，普通 bootstrap 可能给出退化区间，不能据此声称质量
已获统计保证。预注册每题第一次运行为独立配对的质量主分析，使用配对二元比例差的 score
区间；第 2/3 次作为稳定性复验，全部重复的 task 聚类统计作为补充。少量零故障样本也不能
证明总体故障率为零；需同时报告任务数、切换数及模型/来源覆盖。

正式参数运行前冻结：安全高水位、完整请求低水位、D 提示、延后策略、摘要长度和所有预算。
70K/90K/40K 可作先导起点，不在正式集上反复挑选获胜阈值。质量区间太宽、压缩覆盖不足、
有效交付数过少或成本区间跨零，结论是证据不足；增加新的独立任务或保留纯 A，而不是宣称
“没有显著差异，因此一样好”。

所有故障和恢复成本都纳入分析。调整实现后使用新版本完整记录重测，保留失败版本；正式样本
若反复被用于调参，就降级为开发数据，并补新的确认样本。

## 7. 观测补齐与产物

现有[压缩有效性脚本](../scripts/run_compaction_effectiveness.py)直接调用 `ContextCompactor`，
适合复用 transcript 加载、故障 Provider、不可变性和输出采集；它不执行完整 Agent 工具链，
也不支持新的 A/D/AD 变体。现有 `a0/a1/a2a/a2b` 名称与本方案 A/D 无对应关系。
需要扩展真实 `AgentRunner` 的策略入口、交接协议及续跑 harness 后才能执行本方案，不能仅
给旧脚本换一个 `--variant ad` 就声称已经测过。现有[效率指标](context-efficiency-benchmark-metrics.md)
的逐请求采集可复用，但要补明确的触发和发布事件，不能只靠最后一条消息名字猜阶段。

建议新增以下产物；均为拟议格式，本轮未生成实验结果：

| 产物 | 必需内容 |
|---|---|
| `manifest.json` | commit、任务/镜像/fixture hash、模型配置、阈值、预算、价格快照、随机顺序、分桶与评分规则 |
| `requests.jsonl` | run/task/repeat、request ID、phase、trigger、context version、输入/输出/原生 usage、耗时、finish/error、成本来源 |
| `handoffs.jsonl` | 唯一 episode/candidate/publication ID、source 范围及版本、D/A 入口、延后/修复、before/after、首个续跑结果 |
| `tasks.csv` | 官方得分、正常完成与停止原因、全阶段费用、输入、墙钟、D/A 次数、切换后有效推进 |
| `quality.jsonl` | 隐藏检查项、期望证据版本、实际产物、错误归因；不把答案注入 Agent 上下文 |
| `comparison.json` / `report.md` | 配对差、分桶结果、区间、覆盖率、缺失数据、失败清单及门禁结果 |

计费记录以 Provider request ID/本地尝试 ID 去重；stream 中多次累计 usage 不能当多次费用累加。
记录元数据和原始计费字段，完整请求仅在受控实验产物中按需保存，不向 Git 提交凭据或完整
私人会话。摘要内容与证据引用可审计，不能只有一行“压缩成功”。

## 8. 执行预算和最终报告

L1 冒烟和 L2 得到每桶实测费用后，按“待执行数量 × 每桶保守单次费用 + 预留复测费用”制定
正式批次预算；给出预计值与单任务硬上限形成的最坏上限。不得把旧的仅摘要回放 $0.50 预算
直接套用到完整工具任务。批次额度覆盖所有策略、辅助调用、失败、复测和在途请求；没有完成
整个配对区块的余额时不启动下一区块。各组执行限制相同，预算停止不能通过重启 Run 绕过。

最终报告先回答“交付是否保持/提高、每次有效交付省多少钱、相对纯 A 的 D 增量是多少”，
再用缓存曲线、切换次数和错误分布解释原因。所有单项百分比附分子/分母、样本范围和费用
完整性。若测试失败或覆盖不足，明确报告不采用/继续验证的原因，不把方案目标写成量化结果。
