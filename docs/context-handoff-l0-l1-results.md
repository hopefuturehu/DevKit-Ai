# A+D 交接测试：L0/L1 完整量化结果

> 2026-09-10 更新：按用户恢复指令完成剩余测试。L0 **37/37 通过**；L1 **36/36 个正式片段、
> 288 个逻辑检查全部执行**。L2/L3 未运行，生产默认入口尚未改成 AD。

本次最明确的收益是容量：在压力 checkpoint 中，CURRENT 切换后平均仍有 **36,472 个估算
tokens**，A 降至 **19,838**，D 为 **21,512**。A 比 CURRENT 再减少 **16,634，约 45.61%**。
充分预热时，A/D 摘要请求缓存命中均超过 99%，但切换后的首个主请求仍需要重建大部分缓存。

完整样本的**可核算摘要加续跑费用**，A 比 CURRENT 低 **29.09%**，强制 D 低 **25.11%**。
这不是账单净收益或整题收益：存在缺 usage 的连接失败，CURRENT 的重复摘要复用了缓存，
三组检查得分也不同。A 的得分为 91/96，CURRENT、D 各 95/96；具体失败原因见第 5 节。

上次 `c9e14ab` 报告的 31.01% / 27.11% 只覆盖三个配齐 checkpoint，本报告以完整样本
替换该阶段性结论。D 的自主交接时机和 AD 的整题增量价值仍需后续实验验证。

### 4.2 缓存复用及其适用条件

| 加权命中率：Σhit / Σinput | CURRENT | A | 强制 D |
|---|---:|---:|---:|
| 正式摘要请求 | 61.87% | 99.47% | 99.43% |
| 正式续跑请求 | 90.44% | 90.52% | 90.76% |
| 摘要 + 续跑 | 87.58% | 92.20% | 92.27% |

审计确认 A/D 的 25 次生成尝试（含 A 的一次失败重试）均保持预热请求的完整原始消息前缀、
模型及工具定义，只在尾部追加摘要指令。**它复用的是摘要生成时的前缀**；三组切换后的首个
主请求均只命中 896 tokens，命中率为 **1.89%—22.87%**，之后才重建为约 90% 的整体续跑命中。

本实验每片段将原始请求预热两次，再生成摘要。99% 是充分预热条件下的结果；真实 Agent
刚收到的新工具输出可能尚未入缓存，不能照搬这个比例。预热开销在费用中另列，没有隐藏。

另一个限制是 **CURRENT 跨片段缓存复用**：其独立摘要请求没有携带主请求的随机项目标识，
同一 checkpoint 两轮摘要请求的 hash 完全相同。CURRENT 第一轮摘要命中率为 **24.01%**，
第二轮 **99.74%**；A 两轮均约 99.47%。SymPy CURRENT 重跑还命中了用户停止前已经生成
过的同一请求，命中从 0.73% 升至 99.75%。这些记录已导出，不能声称各组摘要缓存完全隔离。

## 6. 审计结论、限制与下一步

完整只读审计通过：**6 个冻结 fixture hash、532 份账本请求 hash 和工具协议、517 条完整
usage 费用、36 个正式片段的原始历史不变及最多一个活动摘要**，以及 A/D 的 25 次原始
前缀复用。已保存但未结算的请求单列 hash 和预留，未知费用没有被抹掉。正式源码仍与冻结
manifest 一致。

这些检查来自 6 个固定状态，并非 288 个独立真实任务；部分事实仍在原始尾部或用户锚点中，
8 个问题又按固定顺序连续提问，不能把得分当成摘要正文单独保真率或整题成功率。强制 D
另外发出交接请求，与主模型在自然执行中主动交接的成本结构和时机均不同。模型原生超大
窗口、开放式探索、多次压缩和自主 AD 未在本轮验证。

后续优先处理四项问题，再进入 L2：

1. 修复取消传播：Runner 返回 cancelled 后，评测外层必须停止新检查；本次第一次收尾中
   取消被捕获后仍继续，最终用 SIGTERM 停止。验证取消后 Provider 调用数不再增长。
2. 校准输入预算估算，区分估算与 API usage；用数字日志和历史 reasoning 场景验证预留，
   防止低估时过晚触发 A。短历史保留最小释放门槛。
3. 区分执行器失败说明和模型事实记忆；恢复后明确当前请求仍待执行，验证不再复读旧失败
