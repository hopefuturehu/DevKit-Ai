## 2. L0：正确性和恢复边界

**37/37 通过，退出码 0。** 覆盖无主动交接时 A 兜底、无效/重复交接、输出截断/空输出/
格式错误、摘要输入超预算、巨大工具原子组、有限重试、工具批次闭合、新用户更正、证据文件
版本变化、发布前崩溃/重启/重复回调，以及摘要合格但完整输入仍高压。

其中包含实际子进程 `os._exit(23)` 的发布中断恢复、实际文件改变，以及经过真实 Runner
和文件工具的脚本化 Provider 对照。验证旧状态保留、最多一个活动摘要、源记录不变、预算
不重置。另运行既有压缩回归 **26/26 通过**。

故障注入证明这些测试路径符合预期，不代表真实模型的故障发生率。此次付费测试收尾还暴露
了批次取消问题：Runner 消化取消后，外层评测循环仍继续下一检查；这不在上述发布恢复测试
的覆盖范围内，需要单独修复批次终止传播。

## 3. 配齐子集：质量、缓存、费用与等待时间

以下严格限于相同的三个 checkpoint，每种策略都是 3 次摘要、24 个逻辑检查、30 次续跑
模型请求。预热两次使用原始请求前缀，输出上限 32，输出被丢弃且工具不执行。每片段隔离
随机项目标识，三组都承担同样的预热安排。

| 指标 | CURRENT | A | 强制 D |
|---|---:|---:|---:|
| 摘要发布 / 片段 | 3/3 | 3/3 | 3/3 |
| 事实及必要回读检查 | 24/24 | 24/24 | 24/24 |
| 首个真实工具往返 | 3/3 | 3/3 | 3/3 |
| 严格 JSON 格式通过 | 8/24 | 8/24 | 8/24 |
| 摘要请求缓存命中率 | 2.36% | 98.93% | 98.86% |
| 全部续跑请求缓存命中率 | 89.91% | 89.95% | 89.98% |
| 摘要 + 续跑费用，USD | 0.044090 | 0.030419 | 0.032138 |
| 相对 CURRENT 节省 | — | 31.01% | 27.11% |
| 包含预热的费用，USD | 0.073910 | 0.060242 | 0.061964 |
| 摘要请求等待合计，秒 | 24.33 | 32.86 | 32.17 |
| 摘要 + 续跑请求等待合计，秒 | 95.43 | 100.91 | 103.98 |

缓存命中率为 `Σhit_tokens / Σinput_tokens`，不是各请求命中率的算术平均。
严格格式失败主要是 JSON 前有说明文字；事实评分和格式评分分开，不能把 24/24 事实正确
解释成严格格式全部合格。费用下降也没有带来本子集的模型等待总时长下降。

A/D 在摘要调用中保留原始前缀，减少高价未命中输入。CURRENT 在短片段也能命中公共小前缀，
但 stage-boundary 和 Chess 的摘要命中分别只有 3.96%、0.82%；A 对应 99.30%、99.27%。
**摘要阶段复用缓存不等于切换后保住全部缓存**：三组首个续跑请求只命中 896 tokens，
命中率约 3.31%—22.52%，之后才重新积累到约 90% 的整体续跑命中率。

按 checkpoint 展示，避免总体数字掩盖短任务退化：

| checkpoint | CURRENT 费用 | A 费用 | D 费用 | A 相对 CURRENT | D 相对 CURRENT |
|---|---:|---:|---:|---:|---:|
| short | $0.003503 | $0.004605 | $0.005148 | 增加 31.46% | 增加 46.95% |
| stage-boundary | $0.018965 | $0.017602 | $0.017810 | 节省 7.19% | 节省 6.09% |
| chess-large-tail | $0.021622 | $0.008212 | $0.009180 | 节省 62.02% | 节省 57.54% |

上述费用包含摘要和全部 8 个逻辑检查，排除作为测量准备的预热；预热费用已经在上表另列。
阶段边界和 Chess 的 A/D 从摘要完成时即低于 CURRENT，累计到第 8 个检查仍低于；short
在观察的 8 个检查内没有达到成本平衡。不能据此外推任意后续长度下的成本平衡点。

## 4. 上下文释放：估算与实测必须分开

| checkpoint | 切换前估算 | CURRENT 切换后估算 | A 切换后估算 | D 切换后估算 |
|---|---:|---:|---:|---:|
| short | 3,224 | 3,762 | 4,453 | 5,481 |
| stage-boundary | 23,968 | 20,258 | 21,025 | 21,912 |
| chess-large-tail | 74,709 | 21,866 | 21,903 | 23,464 |

该表使用同一组装器估算完整输入，在续跑前比较同一状态。Chess 的 A 释放 **52,806 个估算
tokens，约 70.68%**；D 释放 51,245。短历史三组均增加输入，说明小上下文不该强制切换。
因为本子集没有跨过 CURRENT 范围限制的有效对照，**尚未证明 A 能比 CURRENT 多释放容量**。

实测 API 的原始预热输入与估算有明显差异：short 约 3,449—3,455，stage-boundary
30,923—30,924，Chess 32,996—32,998。历史 reasoning 等内容的序列化和 Provider
计数口径不同，不能将 74,709 当作 Chess 的实际 API 输入。未执行 near-budget，未覆盖
模型原生窗口接近满或超过压缩器上限的真实请求。

当前 D 原型将交接正文同时保存在活动摘要与尾部原生工具参数中，存在重复输入。三个配齐
checkpoint 的 D 切换后估算比 A 多 **1,028 / 887 / 1,561 tokens**；续跑费用合计也更高。
这是原型实现开销，不是 D 方法必然如此。此次冻结实验中没有中途修改该表示。

## 5. 失败、中断及总费用

v1 三个短片段用于冒烟，原评分器将 JSON 前带说明的回答判成格式失败，且预热改变了末尾
指令。保留原结果，修复为“事实与严格格式分开判分 + 原始前缀预热两次”后冻结 v2；正式
运行中未继续放宽评分。v1 的 36 个请求费用 **$0.018309** 不并入 v2 对照。

v2 在 SymPy D 的第一次预热发生一次 `ConnectError`，没有生成摘要或续跑检查；归档该
失败尝试并保留费用预留后，从同一冻结状态重跑，最终该 D 片段 8/8。这不是摘要截断失败。
10 个未受中断影响的完整片段中，摘要均发布，未见摘要输出长度截断；32-token 预热的
`finish_reason=length` 是预定限长，不算压缩失败。

用户要求收尾时，SymPy CURRENT 的第 2、5 个检查被取消，其余检查中有 4 个通过、2 个
判分不通过；这些后续结果受中断污染，整片段从质量对照排除，原结果仍保留。进程最终以
SIGTERM / 143 停止；SymPy A 留下一个已保存请求但没有结算 usage 的调用。

| 费用口径 | 结果 |
|---|---:|
| v2 已记录请求 | 154，其中 151 个有完整 usage |
| v2 可按 usage 核算的费用 | $0.295894 |
| v1 + v2 可核算费用 | **$0.314202** |
| 未核实费用 | 1 次连接失败、2 次取消、1 个停止时未写入账本的请求 |
| 含这些未知请求的保守预算占用，再加 v1 | **$0.574455** |

未知费用没有填零，也没有冒充实际收费；$0.574455 是本地保守预算预留，不是账单。
费用按 DeepSeek 官方 Flash 价格区分命中、未命中和输出；本轮已知请求处于峰时，归一化
峰时费用与按时间计价相同，无跨价格边界请求。[官方价格](https://api-docs.deepseek.com/quick_start/pricing/)
于 2026-09-09 核对：峰时每百万 tokens 分别 $0.014 / $0.44 / $1.32；尚未与账单对账。

独立只读审计核对 154 份请求 hash 和工具协议、151 条完整 usage 费用、11 个已出结果
片段的原始记录不变及最多一个活动摘要。额外未结算请求单列 hash；中断片段不因此计成成功。

## 6. 后续修复和未完成验证

优先修复评测批次的取消传播：某个检查返回 `cancelled` 后立即跳出批次，未结算请求记录为
取消或费用未知；用“取消后 Provider 调用次数不再增长”的测试验证。此项由本次收尾实际暴露。

其次评估 D 控制调用正文去重，以及短上下文的最小释放门槛。不能在删除控制调用时留下
孤立工具结果；应共同验证活动摘要、工具协议和原始记录可恢复性。

本次结果只验证了受控切换路径和部分缓存收益。剩余 L1 26 个片段（含两个受中断影响片段）
仍待完成；之后才有条件按原方案验证自主触发、超大输入、用户更正和整题收益。本轮不继续
发起付费请求，也不将未完成的 L1 或未运行的 L2/L3 标为通过。
