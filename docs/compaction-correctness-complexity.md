# 压缩正确性与实现复杂度的取舍

日期：2026-09-12。范围：公开源码、论文与本项目已有重放证据。
后续经用户确认，精简版已在 `a_fallback` 实现并通过本地验证；真实模型对照也已完成。
30 次重放及一组短续跑未证明新版整体优于旧版：7 次标题格式回退使平均摘要费用增加 102.8%，
目标旧错误未稳定消除；短续跑产物有所改善，但两版均未通过最终验收。
量化结果见[本轮实验留档](compaction-fidelity-evaluation.md)，本文件保留原设计与本地验证的范围。
完整结论在 CLI 交付，本文用于留档。
源码快照及哈希见[来源清单](data/compaction-complexity-sources.json)。

## 推荐决策

先保留确定性的会话安全检查，通过小范围提示改动、已有原文尾部与按需回读改善摘要质量。
用冻结断点和短续跑评估后，再决定是否增加证据解析或第二轮模型审查。
强制逐条引用、固定证据区和跨轮证据继承暂不作为首版实施项。
这是对[证据增强设计](compaction-evidence-improvement-design.md)实施优先级的调整。
精简版的实施结果如下；重型证据机制仍未实现，模型实测尚未确认提示改动的事实质量收益。

## 实施与验证结果

| 约定事项 | 落地方式 |
|---|---|
| 保留生成与安全机制 | 复用前缀一次、失败后独立一次、候选与预算检查、原子发布；没有新增请求或重试路径 |
| 内容规则具体化 | `strategies.py` 的 `FALLBACK_SUMMARY_INSTRUCTION` 同时用于前缀后缀与独立摘要 system；明确区分推断、调用、返回、验收和旧摘要状态 |
| 保留冲突与失败经验 | 通过同一提示要求关键技术值集中记录、保留互斥解释与待核实状态、记录否决原因；允许简短原文与已有回读线索，不新增格式解析器 |
| 复用原文与按需回读 | `service.py` 在 a_fallback 的恢复上下文中说明核验条件及已有 `load_compaction_source` / `search_session_history` 用法；这段提示也计入压缩后的预算投影 |

current/A/B 的摘要提示保持不变，默认策略和额度配置没有修改。
前缀路径只在后缀增加规则，已有 messages、tools、tool_choice 和 32K 输出额度仍按快照发送。
独立路径沿用配置的输出额度（默认 8K），不增加第二轮事实审查。
恢复提示仅提供核验指导，不自动触发工具，不把原文哈希通过等同于事实正确。

验证结果：

- 定向测试 **54 passed**：压缩策略、基础压缩、完整上下文集成，以及真实 Agent 循环的前缀失败转独立摘要。
- 新增跨两次压缩的回归：父摘要原样传入下一次独立请求，保留用户锚点及原文尾部，旧版和新版摘要均能按范围回读，原始历史哈希不变。
- 真实 Agent 循环确认恢复提示与回读工具可见；原任务仅执行预定的一次工具调用，摘要申请的工具未执行，也没有自动增加回读请求。
- 旧 A32 冻结断点三种模式的离线预检通过，仍选择覆盖 1–40、保留 41–70；产物位于 `artifacts/compaction-fidelity-20260912/offline-preflight/`。该预检不发送摘要请求，不计为模型重放或摘要成功。
- 修改文件的 Ruff lint 与差异空白检查通过；仅整理本次新增代码的格式，未重排其他位置已有的格式差异。

上述测试验证请求组装、保留、恢复及发布行为。测试中的摘要由假 Provider 提供，
不能证明真实模型更少继承错误；按本文第 5 节完成的真实对照及未覆盖项见上述实验留档。

## 1. 哪些正确性值得程序强制保证

| 层次 | 例子 | 合适的处理 |
|---|---|---|
| 会话与协议完整性 | 输出未结束、工具调用未配对、覆盖游标错误、取消后误发布、压缩后仍超预算 | 确定性校验、原子发布、失败保留旧状态；这些检查继续保留 |
| 对历史的忠实程度 | 用户约束遗漏、计划变成完成、存疑推断变成事实、旧错误反复继承 | 摘要规则、必要原文、离线标注与续跑检查；不能仅由格式证明 |
| 外部事实正确性 | 数值解码、测试是否覆盖目标、代码是否满足要求 | 后续行动依赖该结论时读取证据或执行验证；摘要模型自查不等于外部验证 |

合法消息编号只说明能定位来源，原文完全匹配只说明引文没被改写，二者均不证明引文支持解释。
即使摘要忠实复述原对话，原对话本身也可能包含错误。
增加机制前应回答：阻止哪类已出现的错误、引入什么新失败路径、能否用测试或续跑证明收益。

## 2. 开源项目的实际选择

以下比较限于指定公开路径，不推断整个项目所有配置或未公开服务端行为。
普通生成路径不含拆分长回合、API 重试和超限恢复。

| 项目与核对版本 | 主要方案 | 正确性处理与边界 | 相对复杂度 |
|---|---|---|---|
| SWE-agent `3ea751c087f3` 的 LastNObservations | 保留最近 N 次观察，将旧工具输出替换为省略提示；不用摘要模型 | 不引入摘要改写错误，但可能丢失原始反证，也不纠正助手推断 | 最低；可选处理器，非所有配置默认 |
| pi `71dca871bc80` | 结构化摘要、合并旧摘要、保留近期约 20K tokens；维护文件操作记录 | 拒绝错误/长度截断及摘要工具调用；提示保留精确路径与状态。未见通用事实审查门禁 | 低至中；重点是边界、格式和恢复 |
| OpenCode `95daf90670b7` 的 core 路径 | 固定结构、近期原文、旧摘要冲突时优先新对话 | 区分完成/进行中/阻塞，检查调用结果和非空；新说法仍可能错误 | 低至中；纠错主要靠更新提示 |
| OpenHands SDK `9c3571a69454` | 留开头和尾部，摘要中间事件；保留任务 ID/状态 | 检查原子边界和压缩进度；提示区分完成/待办。所查生成路径没有第二轮语义审查 | 中；复杂度集中在分段与超限恢复 |
| Gemini CLI `9c1b0a610534` | 摘要后携带同一段原历史与候选，使用同一摘要模型配置自查 | 第二次请求检查细节、路径、工具结果、用户约束；之后检查非空及 token 缩减。不是独立事实裁判 | 中至高；正常生成固定增加一轮请求 |
| Codex `02a8f038b87a` 公开文本路径，沿用 09-11 核对 | 简洁交接提示、保留预算内用户原文并重建上下文 | 未见逐条事实证明；原生远端压缩内部算法未公开，不能外推其无损性 | 文本路径较简单；原生服务端不可比较 |

## 3. 复杂方案是否一定更好

JetBrains Research 等的 [The Complexity Trap v3](https://arxiv.org/html/2508.21433v3)
比较了 SWE-agent 上五种模型配置的观察遮蔽与 LLM 摘要，摘要没有稳定胜过简单遮蔽。
例如 Qwen3-Coder 480B 在 SWE-bench Verified 上：

| 方法 | 任务解决率 | 平均每题费用，美元 |
|---|---:|---:|
| 原始历史 | 53.4% | 1.29 |
| 观察遮蔽 | 54.8% | 0.61 |
| LLM 摘要 | 53.8% | 0.64 |

这说明简单基线值得保留，不证明遮蔽在我们的模型、长任务和缓存价格下同样更好。
这些是任务结果与费用，不是摘要事实准确率。

论文 D.3 的联合批判/摘要提示未改善解题率，并增加运行开销；它同时反思执行路线，
不等同于 Gemini 另一次原文对照自查。v3 对该实验样本集的介绍与正文/图注不一致，
本文不引用其具体样本量，也不将旧 v1 的费用与长度百分比移植到 v3。

## 4. 本项目首版收窄到什么程度

现有提示已经要求区分假设与事实，再加一句“必须准确”不够。
此前单个冻结断点的四份独立路径摘要中，三份继承了错误常量解释；前缀摘要还出现互斥半径。
这不是总体错误率，也未证明另一条完整任务失败由这些错误造成。

现在建议实验的改动：

1. 两条路径共用具体内容规则：助手普通正文与 reasoning 都可能只是推断；新说法不自动比旧工具证据可靠；旧摘要的未核实状态继续保留。
2. 在现有章节记录未解决冲突、已否决判断及原因；同一技术值集中写一次。已发起、成功返回、验收通过分别表达，不以助手自述代替结果。
3. 关键原始数值或反证可简短原样放进 Critical Context，空间不足保留回读线索；不强制每条引用、额外 JSON、固定三类语法或 500-token 证据区。
4. 复用已有近期原文与历史回读。续跑依赖存疑结论时才核对，不要求摘要模型继续原任务，也不在每轮压缩后全量重读。

维持前缀一次、失败后独立一次，输出额度 32K/8K，摘要目标 3K、硬上限 4K，
完整续跑输入低水位 40K。前缀路径的新规则只追加在摘要后缀，保留原请求前缀；
实际缓存命中按 usage 判断，摘要发布后的前缀重建成本仍然存在。

| 暂缓项 | 维护成本与局限 | 何时重启 |
|---|---|---|
| 强制逐条引用、原文匹配、固定证据区 | 解析、预算划分、旧摘要迁移、跨轮继承；格式失败可能增加冷兜底，仍不证明解释正确 | 多断点证明关键原文丢失造成误操作后，先只保护该类信息 |
| 通用事实库、自然语言矛盾解析器 | 对象、属性、时间和版本归一化本身就是新问题 | 当前证据不足以支撑投入 |
| 固定模型审查 | 多一次请求及耗时，可能误改，仍可能继承同一错误 | 离线能检出有害错误，且续跑收益足以覆盖成本时 |

这是一轮低成本实验，不是宣称提示词能保证零错误。结构化状态如工具返回是否报错，
未来可局部由程序生成，不必先建任意 shell 输出的通用事实抽取系统。

## 5. 怎样决定是否继续增加复杂度

先对比现有 a_fallback 与精简提示版，固定模型、输出额度、摘要预算与环境快照。
已有断点每组五次作为筛查，另覆盖父摘要已含错、后续消息更正旧判断的断点。
随机交错运行，避免把冷热缓存差异误算为方案收益。

报告错误确定结论、约束遗漏、未标注冲突、误改正确内容，同时检查必要信息覆盖率，
避免靠省掉难点降低错误计数。正确修正、降为待核实、信息删除三类结果分开。
随后同快照短续跑：是否沿用错误值、重走否决路线、恢复多花多少读取和时间、实际验收如何。
结构成功率与引用通过率不替代这些行为指标。费用包括摘要、额外校验、缓存重建和返工，usage 缺失单列。

精简版改善结果就停在这里；剩余错误集中在一类信息就只补该类的程序保护。
只有多类语义错误持续造成实际失败，才比较 Gemini 式额外自查。
五次重放不能支持总体准确率、成功率或成本优势的统计结论。
